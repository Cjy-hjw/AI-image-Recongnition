> ⚠️ 2026-09-07 实况修订:原任务书假设 workspace 有完整 src 树,实际云端是
> "训练包解压在 /root/cloud_train_pkg、infer 包 src 已进 workspace"的分裂布局。

做 1 件事:合并 src → 跑诊断脚本 → 回报。不要改代码,不要调超参。
输出**原样**回报,不要总结。

## 0. 合并 src(一次性,训练包的 src 并进 workspace)

```bash
# 先清掉误拷出来的嵌套(如有)
rm -rf /2026aicompetition/workspace/src/src

# /. 结尾 = 拷内容不拷目录本身;cp -rf 覆盖同名文件
cp -rf /root/cloud_train_pkg/src/. /2026aicompetition/workspace/src/

# 验证两条关键 import
cd /2026aicompetition/workspace
PYTHONPATH=/2026aicompetition/workspace/pylibs python -c \
  "from src.dataset.official_loader import build_official_datasets; \
   from src.inference.case_pipeline import diagnose_static_case; print('OK')"
# 必须打印 OK,报错就停,原样回报报错全文
```

诊断脚本(diagnose_detection.py / detection_match.py)放
`/2026aicompetition/workspace/scripts/` 下(如已在训练包 scripts 里,一并 cp 过去)。

## 1. 预检(3 例,约 2-5 分钟)

```bash
cd /2026aicompetition/workspace
PYTHONPATH=/2026aicompetition/workspace/pylibs python scripts/diagnose_detection.py \
    --data-root /2026aicompetition/datasets/training/annotation \
    --xlsx /2026aicompetition/datasets/training/annotation/甲状腺_标注结果_训练集.xlsx \
    --weights /root/cloud_train_pkg/checkpoints/official_heads_seg_best.pth \
    --config /root/cloud_train_pkg/configs/thyroid_config.yaml \
    --samples-pkl /2026aicompetition/workspace/cache/samples.pkl \
    --limit 3
```

- `--weights` 指向 **r5 的 official_heads_seg_best.pth**(诊断对象 = 当前交付权重)。
- 启动第一屏会打印权重绝对路径,确认无误。
- ⚠️ cache 里已是新表 samples.pkl——诊断只用它的 img/mask,临床标签不消费,无影响。

## 2. 全量(无 --limit;nohup 防断,约 30-60 分钟)

```bash
cd /2026aicompetition/workspace
nohup env PYTHONPATH=/2026aicompetition/workspace/pylibs python -u scripts/diagnose_detection.py \
    --data-root /2026aicompetition/datasets/training/annotation \
    --xlsx /2026aicompetition/datasets/training/annotation/甲状腺_标注结果_训练集.xlsx \
    --weights /root/cloud_train_pkg/checkpoints/official_heads_seg_best.pth \
    --config /root/cloud_train_pkg/configs/thyroid_config.yaml \
    --samples-pkl /2026aicompetition/workspace/cache/samples.pkl \
    > /2026aicompetition/workspace/diagnose_r5.log 2>&1 &
tail -f /2026aicompetition/workspace/diagnose_r5.log
```

## 3. 回报清单(全部原样复制,不要总结)

1. 第 0 步的 import 验证输出(OK 或报错全文)
2. 预检 3 例的控制台输出全文
3. 全量末尾的**控制台摘要表全文**(static/dynamic/combined 三池的
   ap_current/ap_oracle/ap_iou_ranked/ap_dedup/match_rate)
4. JSON 报告路径(形如 detection_diag_<时间戳>.json)+ 文件大小
5. runtime 多少分钟、处理多少 case、anomaly 多少条(>0 则贴 report["anomalies"] 前几条)

## 我们要看的(你不用判断,原样回报即可)

| 观察 | 含义 |
|---|---|
| 静/动三池的 ap_current vs ap_oracle 差距 | 排序失真 vs 漏检,谁是主因 |
| 动态 conf 直方图是否挤 ~1.0 | 二值化毁掉排序能力的实锤 |
| ap_dedup − ap_current | 碎裂 FP 稀释量 |
| 临界带 [0.35,0.5) 占比 | 边界形态可挖掘空间 |
| 小面积桶 max-IoU=0 集中度 | 结构性不可检(要 640 分辨率) |
| 主病灶 vs 次病灶匹配率 | 多病灶拆分是否不足 |
