# 云端训练操作手册（r6 轮：2-①/2-② A/B 对拍）

**你要做 5 件事：传文件 → 核对 → 改 2 个数跑第一轮 → 改 3 个数跑第二轮 → 按表回报。**
不要改代码，不要调其它超参，不要自己判断该不该继续。有疑问就停下来问。

> 本轮跑 **2 轮训练**（编号 2-① 和 2-②），每轮约 **40 分钟**（上轮实测 95 秒/epoch
> × 24 epoch ≈ 38 分钟，含预抽取缓存生效；两轮合计约 1.5 小时）。预抽取缓存上一轮
> 已跑完，本轮命令里 `--samples-pkl` 直接用，**不重跑缓存**。目的是对拍 ETE 损失方案，
> 两轮除了指定的几个 config 数字外**其余完全一致**。

## 步骤 2：第一轮（2-①，只关 CB）

### 2.1 🔴 先挪走旧日志（必做，顺序不能反）

JSONL 是**追加**模式，不挪的话新旧两轮 epoch 号混在一个文件里，本轮对拍全废：

```bash
mv /2026aicompetition/workspace/logs/train.jsonl /2026aicompetition/workspace/logs/train_r5.jsonl
```

（若报 No such file 不用停，说明已经挪过，继续。）

### 2.2 改 1 个数

`configs/thyroid_config.yaml` 里找 `ete_cb_beta: 0.9`，改成：

```yaml
  ete_cb_beta: 0.0
```

**只改这一个**。`ete_la_tau` / `ete_qwk_weight` / `ete_dist_weight` 保持 0.0 / 0.0 / 0.2 不动。

### 2.3 起训

先 `nvidia-smi` 确认没有残留进程，然后：

```bash
nohup python -u scripts/train_official.py \
    --data-root /2026aicompetition/datasets/training/annotation \
    --xlsx "<真实xlsx路径>" \
    --resume-from checkpoints/best_model_mixtrain_xl_e40.pth \
    --samples-pkl /2026aicompetition/workspace/cache/samples.pkl \
    --batch-size 16 \
    --epochs 24 \
    --out checkpoints/official_heads_r6a.pth 2>&1 | tee r6a_run1.log &
```

- `nohup` 和 `-u` 都不能少；不要加 `--log-dir`
- 启动第一屏必须有 **3 类**关键行，缺任何一类就停下报我：
  1. **2 行** `Successfully loaded offline local backbone pretrained weights`（ImageNet 骨干）
  2. **1 行** `[warm-start] 加载 checkpoints/best_model_mixtrain_xl_e40.pth;四头 32 键随机初始化(预期)`
  3. **1 行** `[护栏] warm-start val Dice 基线 = 0.xxxx`（基线**必须 > 0.1**，如果 ≈0.000x 说明底座没载进去，停下报我）
- 第一屏若出现 `AssertionError` / `RuntimeError`(任何一条) → **停**，原文发我

⚠️ `checkpoints/best_model_mixtrain_xl_e40.pth` 是上上轮传的
`cloud_train_weights.zip` 里的分割底座。若 `ls checkpoints/` 里没有这个文件，
停下报我，别自己去掉 `--resume-from` 跑（会变成冷启、与 2-② 不同起点）。

## 步骤 4：回报

每轮 **前 3 个 epoch 跑完回报一次**，跑完再回报一次。内容：

1. `pwd` 和你实际用的命令行
2. 启动第一屏（含 2 行 `Successfully loaded...`）
3. 前 3 个 epoch 的**完整日志行**（整行复制，不要摘选）
4. `nvidia-smi` 峰值显存（第一轮内跑一次 `nvidia-smi --query-gpu=memory.used,memory.total --format=csv -l 30`）
5. 第一个 epoch 的 `n_valid_*` 数字（在 JSONL 里，用 `head -2 /2026aicompetition/workspace/logs/train.jsonl`）
6. 出现的任何 `warn` 行原文

**回报规则：原样复制数字和日志，不要总结成"训练正常"这种结论。**

### 两轮都跑完后，额外回报 ETE 对拍四件套（JSONL 里逐 epoch 抽）

```bash
python - <<'EOF'
import json
for tag, path in [("2-①", "train_r6a.jsonl"), ("2-②", "train.jsonl")]:
    p = f"/2026aicompetition/workspace/logs/{path}"
    print(f"\n===== {tag} =====")
    for line in open(p, encoding="utf-8"):
        try:
            d = json.loads(line)
        except Exception:
            print("  [skip 一行解析失败,原样报我]"); continue
        if d.get("epoch") in (1, 5, 10, 15, 20, 21, 22, 23, 24):

                  "kappa=", d.get("ete_weighted_kappa"),
                  "hist=", d.get("ete_pred_hist"),

                  "gap=", d.get("ete_kappa_gap"))
```

## 判断表：什么时候该停

| 现象 | 做什么 |
|---|---|
| 日志里有 `RuntimeError`、`AssertionError`、进程退出 | 🔴 **停**，前后 30 行日志发我 |
| 启动第一屏没有那 2 行 `Successfully loaded...` | 🔴 **停**，报我 |
| 启动第一屏没有 `[warm-start] 加载` 那行，或 Dice 基线 ≈ 0.000x | 🔴 **停**，报我（底座没载进去） |
| `checkpoints/` 里没有 `best_model_mixtrain_xl_e40.pth` | 🔴 **停**，报我，别去掉 `--resume-from` 跑 |
| 显存峰值 ≥24GB | 🔴 **停**，改 batch 12 重启，实测数字发我 |
| `seg_over_half` 到 epoch 8 还是 0 | 🔴 **停**，报我（脚本自己也会停） |
| `seg_p` / `seg_pmax` / `seg_over_half` 前三个数 **前 5 个 epoch 完全不变** | 🔴 **停**，报我 |
| 某个 `n_valid_*` 恒等于 0 | 🔴 **停**，报我 |
| 看到 `[早停 warn]` / `[护栏 warn]` / `[分割 warn]` | ✅ 继续跑，回报时提一句 |
| `val_dice` 是 0.0000 但 `seg_over_half` >0 且在动 | ✅ 继续跑，正常 |
| `t_auc=None` | ✅ 继续跑，正常 |
| JSONL 某行缺 `ete_pred_hist` 等监控键 | ✅ 继续跑，回报时提一句（早期样本不足会缺） |

## 参考数字（对照用，不用背）

- **显存**：上轮 24G 卡上 batch=16 实测约 8.7GB，本轮配置同量级
- **Dice 基线**：本轮带 warm-start 底座，第一屏基线应 **> 0.1**（上轮冷启基线是 0.0007，本轮有底座不该再是它）
- **`n_valid_*`**（batch=16，每批计数）：`mask` 应是 16；其余各头 9~15 都正常，**别因为数字小报错**
- **上轮（r5，35 epoch，冷启）四头峰值**：`composite` 0.6368@ep21、`mal_auc_pr` 0.8988、`loc_auc` 0.7519、`t_auc` 0.7441、`tirads_kappa` 0.6887、`ete_kappa` 0.2086、`val_dice` 0.6535
- 本轮 24 epoch（Stage C 不触发是**预期行为**）+ warm-start 起点，best 应落在 ep10-24 区间、**不低于** r5 同期；与 r5 数字有小幅差异属正常（起点不同），**本轮主角是 2-① vs 2-② 内部对拍**
- **2-① 的 `ete_kappa` 与 2-② 的 `ete_kappa` 才是本轮的主角**：上轮该值 0.2086，两轮各自与之比

## 🔴 回报时的三条纪律（本轮特有，防误读）

1. **两轮的 `ete_logit_mean_per_class` 不能直接比差值** —— 2-② 开了 LA，原始 logits
   会被结构性推高约 3.3 个单位，这是数学必然不是训练异常。**只看绝对值**：
   `z̄3 − z̄0 > 0` 才是报警（对稀有类过度偏移）。
2. **两轮的逐 step 损失对拍只看 `loss_ete_ce`** —— 2-① 有 `loss_ete_focal`、
   2-② 有 `loss_ete_qwk`/`loss_ete_dist`（键互斥），只有 `loss_ete_ce` 两轮都有。
3. 监控键名是 `ete_pred_hist`/`ete_extreme_error_rate`/`ete_kappa_gap`/
   `ete_logit_mean_per_class`（不是任何文档里的 `val_*` 写法）。
