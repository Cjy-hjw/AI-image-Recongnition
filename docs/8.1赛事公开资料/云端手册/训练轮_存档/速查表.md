## 数据

- 一级目录 = PatientId（32 位 hex），二级 = SeriesUid（静态）或同名嵌套（动态）
- **静动判据 = 文件扩展名**：`.dcm` 静态 / `.nii.gz` 动态
- mask：`M_1_mask.nii.gz` 是主病灶，`病灶N_N_mask.nii.gz` 是次病灶
- xlsx 表头在**第 2 行**（代码已处理，别自己改）
- 样本数：静态 5459 + 动态 1167 = 6626

## 日志字段

**stdout 每 epoch 一行**：`train_loss` `val_dice` `seg_p` `seg_pmax` `seg_over_half` `composite` `mal_auc_pr` `loc_auc` `ete_kappa` `t_auc` `tirads_kappa`

**JSONL 每行必有**：`timestamp` `epoch` `step` `phase` `mode` `data_source`

**JSONL train 行另有**：`loss_*`（各子损失）、`n_valid_*`（各头有效标签数，**每批计数**）

**JSONL val 行另有**：上面 stdout 那些指标

> `seg_p`/`seg_pmax`/`seg_over_half` 是分割概率的均值/最大值/过 0.5 的像素占比。
> `val_dice` 要等 `seg_pmax` 超过 0.5 才会开始涨，所以**前期 `val_dice`=0 但 `seg_pmax` 在涨是正常的**。

## 常见问题

| 问题 | 答案 |
|---|---|
| 训练被 SSH 断开杀掉 | 必须用 `nohup`，见操作说明步骤 3 |
| 指标半天不刷新 | 必须加 `python -u` |
| `t_auc` 是 None | 正常，该指标只统计恶性主病灶，样本不够就是 None |
| JSONL 缺某个字段 | 正常，NaN 值会被主动丢弃（写进去会让整行不是合法 JSON） |
| 依赖缺失 | `pip install -r requirements.txt -r requirements-train.txt -i https://mirrors.aliyun.com/pypi/simple/` |
| 某个 `.nii.gz` 读取失败 | 已知有 1 个损坏文件（339 个里 1 个），跳过即可，报我文件名 |
