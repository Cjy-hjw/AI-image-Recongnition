## 这是什么

甲状腺超声多任务诊断系统的**推理服务**（2026 全国医保影像 AI 识图大赛 · 赛道七）。

一个常驻 HTTP 服务：平台 POST 一批影像目录过来 → 逐病例推理 → 每个病例写一份
`prediction.json` + 每个结节一个 `.nii.gz` 掩码 → 回调通知平台。

**不是**跑一次就退出的脚本。进程退出 = 评测失败。

## 目录总览

包内共 **41 个 `.py`** —— 这是 `python -m src.service.app` 的完整 import 闭包，
一个不多一个不少。仓库里其它目录（训练、数据集加载、损失函数）推理路径用不上，
没有打进来。

```
src/
├── service/     ← HTTP 层：收请求、发回调、找病例（6 个）
├── inference/   ← 推理层：读图、前向、后处理、写官方格式（13 个）
├── models/      ← 模型层：网络结构与四个官方分类头（14 个）
├── gatekeeper/  ← 影像真伪审计（5 个，赛道七不计分，纯防御）
└── utils/       ← 报告生成与热力图（3 个）
configs/thyroid_config.yaml   模型与推理配置
requirements.txt              依赖清单
```

## src/service —— HTTP 层

| 文件 | 职责 | 出问题时 |
|---|---|---|
| `app.py` | FastAPI 应用。`POST /call` 收任务、`GET /health` 供平台探针 | 服务起不来 / 探针不通先看这里的启动日志 |
| `tasks.py` | 把推理任务丢线程池异步执行，跑完回调平台 | 平台等不到回调 → 看这里的回调重试日志 |
| `runner.py` | 批量推理主循环：遍历病例 → 逐个推理 → 写盘。**权重从这里加载** | 每个病例都 FAILED → 多半是权重路径不对 |
| `case_discovery.py` | 扫描 `dataset_path`，把目录解成病例列表。按扩展名分静/动态 | 日志说"未发现任何病例" → 输入目录结构不对 |
| `config.py` | 所有环境变量与默认值的单一出处 | 想知道某个变量默认值查这里 |

**关键约束**：
- 端口固定 **8000**，路径固定 `/call` 和 `/health`（官方规范，不可改）
- `/call` 必须 **5 秒内**返回 200 —— 所以它只解析参数就丢线程池，不等推理
- 探活探针 30 秒一次，**连续失败 3 次平台就重启容器** → `/health` 必须极轻
- 推理线程数**必须为 1**（模型非线程安全）

## src/inference —— 推理层

| 文件 | 职责 |
|---|---|
| `case_pipeline.py` | 单病例推理核心，静态图/动态图两条链路 |
| `model_runner.py` | 建模型、加载权重、前向（含精度控制 fp16/fp32） |
| `io.py` | 静态 DICOM 读取 + 患者隐私字段脱敏 |
| `nifti_io.py` | 动态 `.nii.gz` 读取 + 掩码按官方格式落盘 |
| `nodule_split.py` | 整图分割结果 → 拆成一个个独立结节实例 |
| `postprocess.py` | 模型原始输出 → 概率/掩码。**四个官方分类头在这里解码** |
| `prediction_json.py` | 按官方 schema 组装 `prediction.json` + 合规校验 |
| `v21_output.py` | 落盘总入口：写 json + 写各结节掩码文件 |
| `video_aggregate.py` | 动态图的抽帧与帧级结果聚合 |
| `calibration.py` | 置信度温度校准（当前无参数文件 → 不校准，属正常） |
| `gatekeeper_runner.py` | 调用真伪审计并组装结果 |
| `export.py` | 导出调试产物（CLI 旁路用，服务路径不走） |

## src/models —— 模型层

主网络 `multi_task_model.py`，一次前向同时产出：

- **分割掩码** —— 结节在哪
- **良恶性概率**
- **四个官方分类头**：
  - `heads/location.py` —— 病灶位置（7 类：左上/左中/左下/右上/右中/右下/峡部）
  - `heads/extension.py` —— 甲状腺外侵犯（4 级：无/包膜/软组织/血管）
  - `heads/clinical_t.py` —— T 临床显著性（有/无）
  - `heads/tirads.py` —— TI-RADS 分级（I~V 类）
- `label_schema.py` —— 上述所有类别编码的**单一权威**

## src/gatekeeper —— 真伪审计

赛道七**已被官方豁免这部分考核**（不计分），保留是纯防御性的。

**权重缺失时的行为是设计好的降级，不是故障**：
- `authenticity_model.pth` 缺失 → 日志打 WARNING、该项标记跳过、**临床诊断照常**
- 看到这条 WARNING 是正常的，不用报告

## 数据流（排障时按这个顺序找）

```
平台 POST /call
   ↓  app.py 收下，5 秒内返回 200
   ↓  tasks.py 丢进线程池
   ↓  runner.py 遍历病例
   ↓  case_discovery.py 按扩展名分静/动态
   ↓  io.py / nifti_io.py 读图
   ↓  model_runner.py 前向
   ↓  postprocess.py 解码概率 + 掩码
   ↓  nodule_split.py 拆成一个个结节
   ↓  v21_output.py 写 prediction.json + 掩码文件
   ↓  tasks.py 回调平台
```

## 产出物长什么样

```
{答案目录}/{evaluation_id}/{PatientId}/prediction.json
{答案目录}/{evaluation_id}/{PatientId}/{序列号}/nodule_001.nii.gz
```

`prediction.json` 里每个结节有这些字段（官方要求，缺一个该项就是 0 分）：

```json
{
  "NoduleID": "N1",
  "MaskFile": "SERIES_UID/nodule_001.nii.gz",
  "Detection":  {"confidence": 0.92},
  "Malignancy": {"predicted": true, "confidence": 0.96},
  "TI_RADS_Class": 5,
  "ExtrathyroidalExtension": 2,
  "Location": 4,
  "LocationProbs": [0.01, 0.02, 0.03, 0.85, 0.04, 0.03, 0.02],
  "T_ClinSig": {"T": 1, "T_conf": 0.92}
}
```

**没有结节的病例也要写 `prediction.json`**，里面 `MaskFiles` 和 `Nodules` 都是 `[]` ——
这是正常输出，不是错误。

## 你最需要知道的三件事

1. **`LocationProbs` 如果是 7 个 0.1428（均匀分布），说明权重装错了。**
   真实预测几乎不可能均匀。这是判断"四个分类头有没有真正生效"最可靠的单条判据。

2. **服务必须一直活着。** 用 `nohup`，不然 SSH 一断进程就被杀。

3. **不要改代码。** 有任何疑问停下来问，改了会破坏本地已经验证过的东西，
   而比赛只有一次提交机会。
