## 第3轮·T分期驱动/动态标注位置/新维度分布（回答3.md）

- **T 有驱动因素**：T 有 1745(35.7%)/T 无 2410(64.3%)。T 有中 N 有占比 43.7%、M 有 9.4%；恶性子集 2405 个中 T 有且 ETE=无 1485 个（85.1%），其中 N 有 742(49.9%)/N 无 743(50.1%)。结论：N 分期是重要驱动**但不是唯一**，T 由多因素综合，不能仅靠体积+ETE 规则。

## 第4轮·目录命名/.dcm属性/推理输入/清晰帧帧号（回答4.md）

- **目录命名初判**：一级目录名（32位 MD5）与 PatientId（34位）及 StudyUid 长度不匹配，初判"内部/检查哈希 ID"（**后被第5轮推翻**，见裁决）。
- **.dcm 属性**（实测 19 个）：全 MONOCHROME2 灰度、单帧（NumberOfFrames=1）、无 JPEG 压缩（原始）、BitsAllocated=16、分辨率多样（576×765/984×1280/819×1456 等）、大小 348KB~1.26MB。**.dcm 非视频，每文件单帧静态图**。
- **推理输入（verification/original）**：3 层嵌套，顶目录 32 位哈希→2 级 DICOM UID→dcm/nii.gz 文件。统计：915 目录、988 个 .dcm、58 个 .nii.gz，确有静态+动态混合，靠扩展名区分。
- **清晰帧帧号**：Excel 无明确 Frame Index 列，Col 45（=142）疑似帧号但未确证（**后被第6轮裁决非帧号**），Col 46 为坐标。

## 第5轮·目录名关联字段确认 + .dcm 像素范围（回答5.md）

- **裁决**：目录名 `9442b50b...` 匹配 Excel **检查级别 sheet Col1（PatientId）**（Row 3046），不匹配 StudyUid。结论：**目录名 = PatientId**（32 位 MD5），同一 PatientId 可有多个 StudyUid。→ 推翻第4轮"不匹配 PatientId"的初判。

## 第6轮·三表关联键 + 清晰帧 Col45 裁决（回答6.md）

- **三表关联键**：**PatientId（Col1）是三张表（检查/序列/ROI级别）的共同关联键**。ROI级别**没有 SeriesUid 列**（Col29 实为 RoiUid，Col8/Col29 值与 Col1 相同）。序列级别 Col14（SeriesLabel）大部分为空。

## 第8轮·Col15 真身 + 动态图关联方式（回答8.md）

- **裁决（关键）**：ROI级别 **Col15 = SeriesInstanceUID**（DICOM 标签），静态图二级子目录名 = SeriesInstanceUID，二者 100% 匹配（2/2 样本）。**StudyInstanceUID = PatientId**（34 位 MD5），不是 Col15。→ 修正第7轮"Col15 不匹配子目录"的误判：是"Col15 匹配 SeriesInstanceUID 而非此前对照的 StudyUid/PatientId"。
- **动态图关联**：通过 **PatientId 直接关联**——子目录名=PatientId（同名嵌套）、文件名=PatientId.nii.gz，无 DICOM 头、无 Series 概念，Col15 不适用（3/3 子目录=PatientId，Col15=子目录 0/2）。
- **最终关联策略**：静态图用 SeriesUID 匹配（`子目录==Col15`，可 DICOM 标签断言）；动态图用 PatientId 直接定位（`{pid}/{pid}/{pid}.nii.gz`）。

## 第13轮·header=1 关键 bug 定位与修复 + TI-RADS 详细评分列真实定位（agent修复并回复.md，2026-08-13）

**前置**：第12轮遗留两条"待核实"——① `_resolve_columns` 能否命中真实 pandas colname；② "详细评分缺75.8%"与 Col58 反推数字不自洽、真实列名未定位。本轮云 agent 直接用真实官方 xlsx（`/root/docs/甲状腺_标注结果_训练集_(1) - 新.xlsx`，7919 行×74 列，Sheet=ROI级别）复核，两条均已解决。

**一、根因定位：`pd.read_excel` 默认 `header=0` 读错行**：官方 xlsx 是合并单元格表头，真实列名在第2行（0-based `row=1`），第1行是分组标题（如 `ROI->CLINICAL->`）。`official_loader.py::parse_annotation_xlsx` 此前未传 `header` 参数（默认 `header=0`），把分组标题当列名——这正是第12轮"该列无标题"假象的根因，也解释了此前所有基于外部转写文档做的候选列名讨论为何始终对不上真实 DataFrame：没人用带正确 `header` 参数的 pandas 实际读过表。**①已解决**：`_resolve_columns` 本身逻辑没问题，是喂错了输入；改用 `header=1` 后，云端复核列名匹配率 **100%（5/5 核心监督头：malignancy/lesion_loc/extrathy_ext/clin_t_stage/tirads 全部 HIT）**。已修复 `official_loader.py:264`（加 `header=1`）+ 同步改造 `test_official_loader.py` 的 mock xlsx 为同款双行表头结构（`startrow=1`），本地 813 项全套测试通过、0 回归。**不影响已交付生产**：四头至今从未在真实标签上训练过，此 bug 是在"第一次真训"前被本轮实测拦下。
