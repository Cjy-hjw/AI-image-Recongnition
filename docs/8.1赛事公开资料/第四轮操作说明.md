# 云端训练操作手册

**你要做 4 件事：放文件 → 核对哈希 → 起训 → 按表回报。**
不要改代码，不要调超参，不要自己判断该不该继续。有疑问就停下来问。

> 数据格式、类别编码、字段含义这些查 `速查表.md`，不用通读。

## 步骤 2：核对哈希（必做）

```bash
cd <项目根>
sha256sum src/training/schedule_official.py src/training/metrics_official.py \
          src/training/trainer.py src/training/jsonl_logger.py \
          src/training/loop/validate_step.py src/training/loop/train_step.py \
          scripts/train_official.py src/dataset/official_loader.py \
          configs/thyroid_config.yaml
```

**把 9 行输出原样发给我，等我确认后再做步骤 3。**

---

## 步骤 3：起训

先 `nvidia-smi` 确认没有残留进程，然后：

```bash
nohup python -u scripts/train_official.py \
    --data-root /2026aicompetition/datasets/training/annotation \
    --xlsx "<真实xlsx路径>" \
    --samples-pkl /2026aicompetition/workspace/cache/samples.pkl \
    --batch-size 16 \
    --out checkpoints/official_heads_seg_best.pth 2>&1 | tee official_train_r5.log &
```

- `nohup` 和 `-u` 都不能少
- 不要加 `--resume-from`，不要加 `--log-dir`
- 启动第一屏必须有 **2 行** `Successfully loaded offline local backbone pretrained weights`，没有就停下报我

起训后第一个 epoch 内跑一次：

```bash
nvidia-smi --query-gpu=memory.used,memory.total --format=csv -l 30
```

峰值 ≥24GB 就停掉，改 `--batch-size 12` 重启，并把实测数字发我。

## 步骤 4：回报

每个 epoch 的日志行长这样：

```
Epoch 05/35 [...] train_loss=... val_dice=... seg_p=... seg_pmax=... seg_over_half=... composite=... mal_auc_pr=... loc_auc=... ete_kappa=... t_auc=... tirads_kappa=...
```

**前 3 个 epoch 跑完就回报一次**，内容：

1. `pwd`
2. 启动第一屏
3. **前 3 个 epoch 的完整日志行**（整行复制，不要摘选）
4. `nvidia-smi` 峰值显存
5. 第一个 epoch 的 `n_valid_*` 数字（在 JSONL 里）
6. 出现的任何 `warn` 行原文
7. 你实际用的命令行

之后每 10 个 epoch 回报一次，内容同上第 3 项。

**回报规则：原样复制数字和日志，不要总结成"训练正常"这种结论。**

## 判断表：什么时候该停

| 现象 | 做什么 |
|---|---|
| 日志里有 `RuntimeError`、进程退出 | 🔴 **停**，把 abort 前后 30 行日志发我 |
| 启动第一屏没有那 2 行 `Successfully loaded...` | 🔴 **停**，报我 |
| 显存峰值 ≥24GB | 🔴 **停**，改 batch 12 重启 |
| **`seg_over_half` 到 epoch 8 还是 0** | 🔴 **停**，报我（脚本自己也会停，报错里带 `seg_no_foreground`）|
| `seg_p` / `seg_pmax` / `seg_over_half` 三个数**前 5 个 epoch 完全不变** | 🔴 **停**，报我 |
| 某个 `n_valid_*` 恒等于 0 | 🔴 **停**，报我 |
| 看到 `[早停 warn]` / `[护栏 warn]` / `[分割 warn]` | ✅ **继续跑**，回报时提一句 |
| `val_dice` 是 0.0000，但 `seg_over_half` **大于 0 且在动** | ✅ **继续跑**，正常（前景很小，dice 起得慢）|
| `t_auc=None` | ✅ **继续跑**，正常 |
| JSONL 某行缺某个字段 | ✅ **继续跑**，回报时提一句 |

> ⚠️ **`seg_over_half` 是本轮最该盯的一个数**（预测出来的结节像素占比）。
> 上一轮它全程是 0 —— 模型一个结节都没输出，四个头分数再高也一分拿不到。
> 它 >0 才说明分割真的在出东西。`seg_pmax` 涨但 `seg_over_half` 仍是 0 **不算正常**。

## 参考数字（对照用，不用背）

- **显存**：batch=16 预计比上一轮高约 8GB，正常应在 20GB 左右
- **`n_valid_*`**（batch=16，每批计数）：`mask` 应是 16；其余各头 9~15 都正常，**别因为数字小报错**
- **上一轮四头峰值**（本轮应不差于此）：`mal_auc_pr` 0.888、`tirads_kappa` 0.705、`loc_auc` 0.740、`t_auc` 0.728
- **上一轮 `seg_*` 的值**（全程不变，本轮应该要动）：`seg_p`≈0.445、`seg_pmax`≈0.446、**`seg_over_half`=0（最关键，本轮必须 >0）**
