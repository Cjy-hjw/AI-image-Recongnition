推理服务api要求
参赛队伍应严格按照本节说明开发推理服务，否则可能无法启动测评容器和参与评分，直接影响比赛成绩。
推理服务说明
推理服务要求实现测评内容接收以及推理结果回调2个交互。
交互一： 测评内容接收
选手需要提供HTTP推理服务，api接口路径固定为 /call ，端口固定为8000。提供POST调用方式，content-type为application/json，无认证权限拦截。推理服务应采用异步响应的方式，接收指定格式的body格式内容，并立即响应以表示接受到推理请求（HTTP状态码回复200），系统请求选手推理服务接口5s后未收到响应将判定推理服务请求超时异常。入参body示例如下：{
  &quot;request_id&quot;: &quot;2f4f3f2a-6320-44c2-bd49-de29bd64dc09&quot;,
  &quot;team_id&quot;: &quot;2054451790241292288&quot;,
  &quot;track_code&quot;: &quot;2eaf6e36583b4d06af0f4582220956d0&quot;,
  &quot;input&quot;: {
    &quot;evaluation_id&quot;: &quot;454899866564564&quot;,
    &quot;dataset_path&quot;: &quot;/data/testset&quot;
  }
}
 
input.dataset_path即推理的测评数据集所在目录，存在批量的测试数据样例，选手的推理服务api应支持批量的数据文件读取。
推理接口实例：
curl -X POST http://127.0.0.1:8000/call \
  -H &quot;Content-Type: application/json&quot; \
  -d '{
    &quot;request_id&quot;: &quot;2f4f3f2a-6320-44c2-bd49-de29bd64dc09&quot;,
    &quot;team_id&quot;: &quot;2054451790241292288&quot;,
    &quot;track_code&quot;: &quot;2eaf6e36583b4d06af0f4582220956d0&quot;,
    &quot;input&quot;: {
      &quot;evaluation_id&quot;: &quot;454899866564564&quot;,
      &quot;dataset_path&quot;: &quot;/data/testset&quot;
    }
  }'
  
交互二： 回传推理结果
模型推理完成后，选手需要将结果集放在指定目录，并调用回调系统推理结果接口来表示该次推理完成。
回传推理结果接口地址为：{训推平台服务地址}/api/competition/inference/callback/ 使用POST调用方式，无认证权限拦截，选手需要按照规范传入指定入参body。
body入参示意：
{
    &quot;request_id&quot;: &quot;2f4f3f2a-6320-44c2-bd49-de29bd64dc09&quot;,
    &quot;evaluationId&quot;: 454899866564564,
    &quot;predPath&quot;: &quot;canswer/454899866564564&quot;
}
训推平台完整回调地址已在容器实例的页面上方显示，可直接拷贝用于推理服务的回调请求。

推理服务的结果集predPath输出路径格式为/2026aicompetition/workspace/answer/{evaluation_id}/{结果集}，其中evaluation_id由赛事组在调用推理服务时传入，每次调用推理服务时的evaluation_id均不相同，选手需要将该evaluation_id作为推理结果集路径的前缀路径。例如：/2026aicompetition/workspace/answer/454899866564564/{结果集}。 
其中/2026aicompetition/workspace/answer已由系统统一创建，{evaluation_id}目录需要选手代码内实现动态创建
2、选手需要把推理服务/call 接收到的request_id 和 evaluation_id保存起来，在callback回调推理结果的时候作为入参回传，否则无法闭环单次请求测评，回调接口参数校验会不通过。
 此外，启动推理服务时，须确保启动命令是一个长期运行的前台进程，例如：
python -m vllm.entrypoints.openai.api_server \
  --model deepseek-ai/DeepSeek-V4-Pro \
  --tensor-parallel-size 8 \
  --max-model-len 8192 \
  --trust-remote-code …… 
如果不是前台进程，将无法确保服务持续运行。vllm启动命令满足此要求。

推理服务代码示例
注意以下代码仅为帮助参赛团队快速开发推理服务提供的伪代码，选手应自行实现具体的推理逻辑。

&quot;&quot;&quot;代码示例&quot;&quot;&quot;
import json
import threading
import urllib.request
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
from pathlib import Path

ANSWER_BASE = Path(&quot;/2026aicompetition/workspace/answer&quot;)
CALLBACK_URL = &quot;http://10.1.13.241:80/api/competition/inference/callback/&quot;

def callback(request_id: str, evaluation_id: str) -&gt; None:
    &quot;&quot;&quot;通知平台：推理结果已写入 predPath。&quot;&quot;&quot;
    payload = {
        &quot;request_id&quot;: request_id,
        &quot;evaluationId&quot;: evaluation_id,
        &quot;predPath&quot;: f&quot;/2026aicompetition/workspace/answer/{evaluation_id}&quot;,
    }
    request = urllib.request.Request(
        CALLBACK_URL,
        data=json.dumps(payload).encode(&quot;utf-8&quot;),
        headers={&quot;Content-Type&quot;: &quot;application/json&quot;},
        method=&quot;POST&quot;,
    )
    try:
        with urllib.request.urlopen(request, timeout=30):
            pass
    except OSError:
        # 示例中不处理回调重试；生产服务可在此加入重试或告警。
        pass

def run_inference(request_id: str, evaluation_id: str) -&gt; None:
    &quot;&quot;&quot;在后台线程中执行推理并回调平台。&quot;&quot;&quot;
    (ANSWER_BASE / evaluation_id).mkdir(parents=True, exist_ok=True)

    # 模型进行推理服务，生成推理结果
    # 请将推理结果写入 /2026aicompetition/workspace/answer/{evaluation_id}/

    callback(request_id, evaluation_id)

class InferenceHandler(BaseHTTPRequestHandler):
    &quot;&quot;&quot;无认证的 POST /call 接口。&quot;&quot;&quot;

    def do_GET(self) -&gt; None:
        if self.path != &quot;/health&quot;:
            self.send_error(404)
            return

        body = b'{&quot;status&quot;: &quot;active&quot;}'
        self.send_response(200)
        self.send_header(&quot;Content-Type&quot;, &quot;application/json&quot;)
        self.send_header(&quot;Content-Length&quot;, str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def do_POST(self) -&gt; None:
        if self.path != &quot;/call&quot;:
            self.send_error(404)
            return

        try:
            content_length = int(self.headers.get(&quot;Content-Length&quot;, &quot;0&quot;))
            payload = json.loads(self.rfile.read(content_length))
            request_id = payload[&quot;request_id&quot;]
            input_data = payload[&quot;input&quot;]
            evaluation_id = input_data.get(&quot;evaluation_id&quot;) or input_data[&quot;evaluationId&quot;]
        except (KeyError, TypeError, ValueError, json.JSONDecodeError):
            self.send_error(400, &quot;invalid request body&quot;)
            return

        threading.Thread(
            target=run_inference,
            args=(request_id, str(evaluation_id)),
            daemon=True,
        ).start()

        body = b'{&quot;status&quot;: &quot;received&quot;}'
        self.send_response(200)
        self.send_header(&quot;Content-Type&quot;, &quot;application/json&quot;)
        self.send_header(&quot;Content-Length&quot;, str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, format: str, *args) -&gt; None:
        pass

if __name__ == &quot;__main__&quot;:
    ThreadingHTTPServer((&quot;0.0.0.0&quot;, 8000), InferenceHandler).serve_forever()

 测评容器健康检查要求
 测评阶段需要创建容器类型为测评容器的容器实例，确保测评容器成功运行，才能在测评平台发起测评。

创建测评容器实例时，需要保证整个测评过程中容器实例一直处于运行中状态，如果容器实例发生异常，平台将自动重新启动该容器实例。
为保证平台能够检测到容器实例的运行状态，需在启动命令中启用健康检查服务，监听8000端口，接口路径为 /health，供平台检测。推理平台会自动监听8000端口，定期检查/health接口，以此确定推理服务，于活动状态。平台将启用启动、探活两个探针，推理服务需按规范提供健康检查接口，其中：
启动探针 ：5秒检查一次，最长等待1800秒（30分钟），请确保推理服务在30分钟内完成启动；容器启动成功后，将等待60秒进入就绪状态；
探活探针：30秒检查一次，若探活失败3次，平台将自动重启测评容器实例。
推理服务如果使用vllm框架，框架自动提供上述接口供探活使用，如果使用自定义框架或其他框架，需在8000端口提供/health服务，或将平台对/health接口请求转发到框架提供的健康检查接口，确保该接口返回HTTP 200状态码。

注：训练阶段用的普通容器无法进行测评，不满足以下条件，将无法发起测评，赛事管理平台会显示推理服务状态异常

输出文件格式
金标准格式说明
标注结果的文件格式为.nii.gz，输出目录结构如下，一级目录命名为患者号：
 
影像原始数据为dicom格式，mask为.nii.gz格式，输出命名为M、病灶，对病灶进行分类以及tirads分级标注，输出.xlsx表格如下：
 
表格字段介绍：
PatientId：脱敏后患者号；
AccessionNumber：脱敏后检查号；
SeriesUid：脱敏后序列号；
DetailDescription：序列描述；对于序列扫描期相的描述，一般包含层厚和期相内容；
RoiName：标注结果名称，类别为：M、病灶；
RoiVolume： ROI体积（面积）
RoiVoxelCount：ROI体素数
RoiHUMaxValue：图像强度/HU(最大)
RoiHUMinValue：图像强度/HU(最小)
RoiHUAverageValue：图像强度/HU(平均)
RoiHUStandardDeviation：图像强度/HU(标准差)
STUDY-&gt;CLINICAL-&gt;备注：分为7种类别：重点审核、图像质量问题跳过、序列缺失跳过、构建失败跳过、报告缺失跳过、阴性数据跳过、无；
ROI-&gt;CLINICAL-&gt;良恶性：分为3类：良、恶、无；
ROI-&gt;CLINICAL-&gt;TI-RADS：分为5类：I类/II类/III类/IV类/V类；
cancer_label：甲状腺癌存在标签，2类：阳性、阴性；
patho_histology：病理结果 - 组织学，分为5类：恶性肿瘤、非肿瘤性、交界性肿瘤、良性肿瘤、无；
extrathy_ext：甲状腺外侵犯，分为6类：甲状腺包膜、毗邻软组织、血管、无、无病灶（阴性）、NA/UNK；
esion_loc：主病灶位置，分为9类：左上叶、左下叶、左中叶、右上叶、右下叶、右中叶、峡部、无（阴性）、NA/UNK；
clin_t_stage：临床显著性分级（T），2类：有、无。
 
 
预测输出格式说明
推理输出格式文件夹：推理结果输出至回调 predPath 指定的根目录，包含所有要求目标。静态图和动态图均以 PatientId 作为一级病例目录名，每个病例的预测结果固定保存为 &lt;PatientId&gt;/prediction.json。prediction.json 中保留字段名 StudyUID，但其值必须统一填写 PatientId。；prediction.json 文件名固定，不得改名。例如：
静态图病例目录：
{PatientId}/prediction.json
{PatientId}/{SeriesUid}/{mask_name}.nii.gz
动态图病例目录：
{PatientId}/prediction.json
{PatientId}/{AccessionNumber}/{mask_name}.nii.gz
推理输出格式与金标准相似，在目录下分两层文件夹存放，静态图病例为{PatientId}/{SeriesUid}，动态图为{PatientId}/{AccessionNumber}，其分割掩码mask文件格式为.nii.gz，并且应保证所有的mask文件均能正确与prediction.json对应字段一致。
所有分割掩码必须为 .nii.gz 文件。prediction.json 中的 Prediction.MaskFiles 和 Nodules[].MaskFile 均填写相对于病例一级目录的路径，例如：SERIES_UID/nodule_001.nii.gz
MaskFiles 与所有 Nodules[].MaskFile 必须一一对应：两者集合完全相同、数量相同、不得重复；每条路径必须指向当前病例目录内实际存在的对应掩码文件，不得使用绝对路径或 ../ 越界路径。重要说明：甲状腺外侵犯、主病灶位置、T临床显著性分级仅对主病灶标注，评估时仅针对匹配成功的主病灶。
 
 
模型输出格式
参赛模型需为每个预测结节输出与金标准格式严格一致的分割掩码文件。
静态数据
每个预测结节输出一个独立的二值分割掩码文件（2D NIfTI格式，.nii或.nii.gz），存放于 {PatientId}/{SeriesUid}/。
每个文件为二值掩码，像素值1表示结节区域，0表示背景。
阴性病例（无结节）仍须输出 {PatientId}/prediction.json，其中 Prediction.MaskFiles 和 Prediction.Nodules 均为 []，不输出掩码文件。
动态数据
每个预测结节输出一个独立的三维分割掩码文件（3D NIfTI格式，.nii或.nii.gz），存放于 {PatientId}/{AccessionNumber}/，z轴对应帧序列，与输入视频的帧序列对齐。
每个文件为二值掩码，z轴每个切片上像素值1表示该帧的结节区域，0表示背景。
模型应在所有帧上输出分割结果（即三维nii中每个z切片对应一帧的预测）。评估时仅对标注帧进行指标计算，未标注帧不纳入评分。注意：尽管评估仅计算标注帧的指标，但模型必须输出包含完整视频序列（所有帧）预测结果的3D NIfTI文件，且帧数顺序需与输入视频严格对应，以便评估脚本正确提取对应切片。
阴性病例仍须输出 {PatientId}/prediction.json，其中 Prediction.MaskFiles 和 Prediction.Nodules 均为 []，不输出掩码文件。
通用格式要求
强制格式：必须使用NIfTI格式（.nii 或 .nii.gz），可在文件头中保存像素间距、原点等空间元数据。
像素编码：每个文件为二值掩码，像素值1表示结节区域，0表示背景。
空间一致性：所有掩码文件的尺寸（Height × Width）必须与对应的原始输入超声图像完全一致。
主病灶标识规则
金标准标识：在标注团队提供的临床数据表格中，“RoiName”列的值为“M”的结节即为主病灶。非主病灶在上述字段为病灶1、病灶2,以此类推。
参赛者须知：模型应对所有检出的结节均输出完整的属性字段（Malignancy、TI_RADS_Class、ExtrathyroidalExtension、Location、T_ClinSig等），评估脚本会根据空间匹配结果自动判定哪个预测结节与主病灶对应。
