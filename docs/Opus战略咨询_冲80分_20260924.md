# Opus 战略咨询:冲 80 分可行性与 6 天战术(2026-09-24 深夜)

> **结论**:6 天内 80 分**数学上不可达**(P<0.1%)。它相当于 Dice 和 AP 两项同时做到约 0.98,或者七个子项每项都拿出本赛季最大单步增幅的 5~8 倍。**实际上限:P50≈70.1,P90≈70.7,极限≈71.3。建议瞄准 70.2**,第一目标是最终提交不出事故。
> 另外发现 3 个会误导明天决策的"尺子"问题,都能零成本修:①诊断脚本的位置指标错了一位(off-by-one);②+0.50 晋级线过严,约 4 成概率会把一个真实为正的 L1 挡掉;③L1/L2 快照放在 `/root`,平台重启就会清空,目前没有备份。
> 置信度标注:🟢 有代码/数字实证 🟡 有推理依据但样本少 🔴 推测

## ② 6 天内的现实抓手与可达上限

### 2.1 L1 ep20 上线:净增约 +0.55(80% 区间 +0.25~+0.85)🟡
- **ep16 先例** 🟢:本地静态 Δ匹配 +2.51pt / ΔAP +2.95pt。
  - 线上检测部分 +0.87(Dice +0.51、AP +0.36)。
  - 分类稀释 -0.17(良恶性 -0.07、T -0.10,T 由目标四的差值反推、ETE -0.01、位置 +0.01)。
  - 净 +0.71。
- **L1 的本地增量约是 ep16 的 0.76 倍**(+1.97/+2.18),动态多救回 4/71 个病灶。
  - 线上检测部分约 +0.66~0.70。
  - 稀释按救回病灶数折算,约 -0.13~-0.17。
  - 净约 **+0.55**,**P(≥+0.50) 约 58%**。
- 置信度只到🟡,因为本地到线上的传递比例只有 ep16 一个样本点。

### 2.2 "L1 没到平台、还在涨"这个说法不成立 🟢
- 静态 GT 共 1117 个(P0 数据反推:919/0.8227 = 946/0.8469 = 1117),所以 Δ匹配 0.0009 = 1 个病灶。
- **静态匹配**:L1 五个快照的 Δ匹配分别是 +0.0134 / +0.0188 / +0.0197 / +0.0188 / +0.0197,换算成病灶是 **+15 / +21 / +22 / +21 / +22 个**。**从 ep8 开始就平了**,之后只在 ±1 个病灶内抖动。
- **AP**:+1.33 → 1.71 → 2.01 → 2.24 → 2.18pt,**ep16 见顶**。
- **动态**:从 30/71 到 34/71,只多 +4 个病灶,单点统计力很弱。"动态增幅是两倍"说的其实是 4 个对 2 个。
- → **续训或加大权重的依据不足。** 这个机制能推过 0.5 线的临界带病灶,基本已经收割完了。

### 2.3 分类侧没有活口,而且本地尺子系统性偏高 🟢
- 同一份 r5 权重在三个口径下的数字:

  **线上和旧表接近**,Q7 新表 val 偏高约 0.2。只有 ETE 例外:线上 0.563 与新表 0.5264 接近。

- 结论:分类侧的决策只看线上分项,不再看新表 val。

## 附录 A:诊断脚本位置指标 off-by-one 的证据链 🟢

1. `src/inference/prediction_json.py:97-123`:`location_label_to_index` 返回 **0-based**(`return code - 1`)。
2. `src/dataset/official_loader.py:418-419`:`labels["lesion_loc"] = int(loc)`,**已经是 0-based**。
3. `scripts/diagnose_detection.py:385-395,416`:`_clinical_labels_of` 把 `labels["lesion_loc"]` 原样写进 sidecar 的 `clinical`。
4. `scripts/compare_detection_runs.py:180-188`:**又减了一次 1**。注释里说 clinical 快照存的是码值 1..7,这与事实不符。这段代码由 commit `e93427b` 引入。
5. 后果:
   - 左中叶被并进左上叶那一列,左下叶用了左中叶那一列,……,峡部用了右下叶那一列;
   - 诊断得到的位置 AUC 是 **0.6136**(`训练日志/架构A诊断.md:24`),同一模型在训练侧是 **0.9483**(`训练日志/seg_only.md:8`)。
6. `tests/test_compare_detection_runs.py` 的 fixture 用 `lesion_loc=2/4` 当码值,沿用了同样的错误假设,**测试和实现要一起改**(本地修复需走 Gate2)。
7. **生产链不受影响**:`v21_output.py:384-395` 直接透传 0-based 的 7 维分布,并输出 `argmax+1`,与官方 `[0]=左上叶(码1)` 对齐。
8. 历次对拍中,两边带着同一个 bug,线上位置分数也没变(9.36→9.37),所以**过去的上线结论不需要翻案**。

## ⑦ 追问:换架构能不能到 80

> **结论**:第 ① 节"检测两项满分也只有 80.59"的算法把分类五项冻结在当前值,这个框法不对。按数据信息量重算:**理想模型在本数据上约能拿 77~85 分,中值约 81**。所以 80 不是物理上不可能,而是大约落在天花板中间。**但要摸到它,七个子项需要同时逼近天花板**,没有任何架构能在 6 天内做到。
> - 换架构冲 80:<0.1%;
> - 现有架构冲到 70.5+:约 18%;
> - **押现有架构。**
>
> 另外找到一个此前没人碰过、也不需要换架构的信息源:**T 的物理尺度**(见 7.4)。先做一次 5 分钟检验再决定。
> 文献数字凭训练知识,未现场检索,统一标🟡;推测性判断标🔴。

### 7.1 分类 19.4 分余量:多少是数据天花板,多少是模型能力

第 9 次跑分分类五项合计 **50.58**,余量 **19.42**(50.75 是第 8 次的口径)。

| 子项 | 线上当前 | 信息天花板(估) | 依据 | 可涨(分) |
|---|---|---|---|---|
| 良恶性 AUC-PR | 0.897 | 0.93~0.95 | 病理金标准;滤泡性病变等超声先天分不清;DL 文献内测 AUC 约 0.85~0.93 🟡 | +0.6~0.9 |
| TI-RADS κ(5 级) | 0.693 | 0.75~0.82 | ACR TI-RADS 专家间一致性:未加权 κ 约 0.4~0.6、有序加权 κ 约 0.6~0.75(Hoang 2018 AJR、Grani 2018 等多读者研究)🟡。模型学的是单一标注源的习惯,对该标注源可以略高于专家间一致性 | +0.7~1.5 |
| ETE κ(4 级,限恶性) | 0.563 | 0.60~0.68 | 包膜级微小侵犯本质上是病理镜下所见,超声基本看不到;超声判 ETE 敏感度约 0.5~0.7,读者间 κ 约 0.4~0.6 🟡;4459:333:81:5 的极端不平衡进一步压低上限 | +0.5~1.6 |
| 位置 AUC(7 类) | 0.703 | 0.78~0.85 | 单帧纵切无法判左右;上中下要看到整叶才能定;医生读单帧也得靠体标或文字 🔴 | +1.0~2.0 |
| T AUC(限恶性) | 0.692 | 无物理尺度约 0.75~0.80;有尺度且标签由尺寸驱动时约 0.85~0.92 | T 分期由大小(1/2/4cm)加外侵定义;目前模型只看得到归一化面积,换机型、换深度设置就会漂 🔴(官方定义未知) | +0.8~3.0 |
| **合计** | **50.58** | **54.8~60.0** | | **+4.2~9.4** |

→ **余量里约 50~70% 是数据信息量锁死的**:ETE 的微小侵犯看不见、单帧位置有歧义、TI-RADS 有标注噪声。**约 30~50% 属于模型能力**,其中最具体的一项是 T 缺少物理尺度。
→ 至于"只有 mask 加五个标签、没有 ETE 细节、没有 T 判据":这类监督对学习目标来说是够的,缺细节标注只影响样本效率,几乎不改变上限。**上限由图像里有没有这些信息决定**,T 缺的恰好是可以从 DICOM 头补回来的尺度。

### 7.2 Oracle 检测的真实账:"50.75 + 30 = 80.75"要打两次折

1. **Dice 和 AP 到不了 1.0**。
   - 甲状腺结节超声勾画的医生间 Dice 约 0.85~0.92 🟡,完美模型对着带噪 GT 也会被封顶;
   - 没标注的真结节会被当成假阳性,拉低 AP。
2. **检测越满,分类人口越难**。现在漏掉的约 13% 主病灶一旦进分类池,分类会被稀释约 -0.3~-0.8。

**逐桶判断能否救回**(分桶数取自 seg_only v1 审计,匹配率 0.8469,与 ep16 同档;ep16 v2 本身没有 sidecar。静态漏检 171 个,L1 ep20 后按 0.8675×1117 反推剩 148 个;动态漏检 42 个,L1 后剩 37 个):

| 漏检桶(v1 审计) | 数量 | 机制 | 任何架构能救回的比例(估)|
|---|---|---|---|
| 近失 [0.35,0.5) | 51 | 边界欠分割 | 约 70%(L1 已拿走约 22 个,剩下约 29 个里还能救约 20 个) |
| 远失 (0,0.35) | 76 | 相邻结节粘连、勾画风格不一致(是否含声晕/囊性部分)、大而不均质的结节只被部分覆盖 | 30~50%(实例分离和更好的表征有帮助,风格差异救不回) |
| 零 IoU | 44 | 完全无响应(表征桶 mech5 共 31 个,不全在此桶):等回声、边界不清、微小,或 GT 本身有疑问 | 20~40%(更强的预训练骨干能救一部分,真正看不见的救不回) |
| 动态 | 42(L1 后 37) | 起止帧上结节处在切面边缘,只剩部分可见,标注主观,拉低多帧平均 IoU | 动态匹配上限约 0.65~0.75(当前 L1 为 0.479)🔴 |

→ **静态匹配的现实上限约 0.91~0.94**:在 L1 基础上还能救 52~76 个。目标 0.95+ 要从 148 个里救约 92 个,超出可救量。
→ **动态上限约 0.70**:0.9 要从 37 个里救 30 个以上,边缘帧救不回。动态只占约 6% 的病灶,全部修好也只值约 +0.3~0.4 分。
→ **检测两项的现实上限约 23~25 分**(当前 18.92,可涨 +4~6)。加上分类 +4.2~9.4、减去稀释约 0.5,**总天花板约 77~85**。

### 7.3 只看理论上限,选哪个范式(不考虑效费比)

现有范式有四条结构性短板:
- 语义分割加连通域,分不开粘连结节;
- **四个分类头整图共享一个值**,多结节图里的分类并不针对主病灶;
- 没有物理尺度;
- 所有图像统一缩放到 512。

**理论上限最高的是"两阶段 ROI 范式"**:
- 第一阶段:用现有分割器出候选;
- 第二阶段:对每个实例在原分辨率上裁 ROI,(a)做 ROI 内掩膜精修,(b)按病灶单独分类,输入 ROI 纹理、全局位置和物理尺寸。

它直接打中上面的短板:粘连能分开,T/ETE/TI-RADS 按病灶算,尺度也有了。

- **完全成熟时的理论增益**:在 L1 约 70.0 的基础上,检测 +1~2,分类 +1.5~3,约到 **72.5~75 分**。
- **缺口压不到 2 分以内**:7.2 中约 3~4 分的检测缺口来自标注噪声和可见性,7.1 中约一半的分类缺口来自信息天花板,任何范式都救不回。
- **其他候选按理论上限排序**:
  1. 大号超声基础骨干:主要救表征桶和分类特征,+1~3,有域差风险;
  2. query 式实例分割(Mask2Former、YOLO-seg):只解决实例分离,+0.5~2,分类不变;
  3. 视频时序模型:动态只占 6% 的病灶,整体上限 ≤+0.4。
- **关于过去 DR 的排除**(YOLO 门禁未触发、Mask2Former 显存、EchoCare 域差):那是效费比层面的判断。**这几个候选在理论上限上本来也不占优**。
- **6 天路径的可信度约 10%**:本地实现 1.5~2 天 → 过夜审核 → 训练加诊断 1 天 → 对拍加线上 1 天,没有任何余量。
- **死因**:
  1. 分类头必须重训,而本赛季四轮分类重训全都没超过 r5;
  2. 推理链要大改,本赛季 5 次零分事故全出在推理链工程上;
  3. 640 分辨率被判死、tiling 出现碎裂,"提分辨率就能改善边界"这个前提本身就存疑。

### 7.4 唯一不用换架构的"新信息"杠杆:T 的物理尺度 🔴 先验证

- **事实** 🟢:
  - `src/`、`scripts/` 里没有任何代码读 PixelSpacing 或 PhysicalDelta(grep 零命中);
  - xlsx 第 22 列有 `Spacing`(像素间距);
  - T 头只吃归一化面积 `nodule_scale`,而且整图共享一个值。
- **假设**:"T 临床显著性"主要由病灶大小决定(例如 >1cm,或 >2cm / >4cm)。官方定义未知。
- **5 分钟检验**(交给云端 agent 做,只用训练集,不碰推理链):
  - **样本**:所有静态、主病灶、恶性、T 有效的样本;
  - **特征**:
    - d_mm = GT 掩膜等效直径 2·sqrt(A/π) × 像素间距。像素间距优先取 DICOM 的 `SequenceOfUltrasoundRegions[0].PhysicalDeltaX`(单位 cm,乘 10),其次 `PixelSpacing`,最后用 xlsx 的 Spacing;
    - 对照组 d_norm = sqrt(A/(H·W)),即模型现在能看到的尺寸;
  - **输出**:AUC(d_mm→T)、AUC(d_norm→T)、阳性率、样本数、spacing 解析率,以及 10/20/40mm 三个阈值下的敏感度和特异度。
- **立项条件**(三条同时满足,否则直接放弃):
  - AUC(d_mm) ≥ 0.80(旧表口径下 r5 的 T 为 0.744);
  - AUC(d_mm) 比 AUC(d_norm) 高至少 0.05;
  - spacing 解析率 ≥ 95%。
- **立项后怎么做**:
  - 推理侧为每个实例重算 T_conf = σ(α·logit(头的 T_conf) + β·ln(d_mm/d0)),α、β、d0 用训练集做逻辑回归拟合;
  - spacing 缺失时回退到原值,沿用现有 `_assert_finite` 做 NaN 保护;
  - 工作量约 1~1.5 天,需走 Gate2、66 项契约验收和一次线上跑分;
  - **截止 09-27 23:59**,来不及就放弃。
- **期望**:
  - 假设成立的概率约 20%,成立时 +0.7~2.0 分,**EV 约 +0.2~0.3**。在 L1 之外,这是 EV 最高的一项。
  - 最坏情况只影响 T 这一项(满分 13.33),有回退值兜底。

### 7.5 直答

- **换架构 6 天冲到 80:<0.1%。** 即便只求 6 天内超过 L1 ep20 的线上分,概率也只有约 5~10%,而且会吃掉交付加固的窗口。
- **现有架构(L1)冲到 70.5+:约 18%**(如果 T 尺度检验过线且按时上线,约 22%);**冲到 70.0+:约 55~60%**。
- **押现有架构。** 顺序:L1 上线 → T 尺度 5 分钟检验(过线才立项)→ 09-27 冻结并彩排。
- 80 分建议作为决赛之后、有完整窗口时的目标(路线是 7.3 的 ROI 两阶段),本周不把它当目标。
