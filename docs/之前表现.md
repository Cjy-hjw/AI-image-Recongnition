## 三、 历次迭代详细技术日志 (Iteration Progress Logs & Code Reality Audits)

### 1. A800 物理对齐精调版 (服务器第1版)
- **测试时间 (北京时间 CST)**：2026-06-20 14:29 (对应服务器 06:29 UTC)
- **备份权重**：`best_model_old.pth.bak` (创建于北京时间 21:10，大小 35.4MB)
- **核心改进**：迁移至 A800 服务器进行长轮数训练。修复 `AUCMLossApprox` 批次期望计算缺陷。
- **实测成绩**：Dice `82.59%` | AUC `78.60%` | F1 `81.17%`
- **代码状态审计**：
  - 曾短暂使用训练期物理对齐强正则，强行在 Stage 3 训练对齐，这导致了分割与分类表征空间的剧烈冲突，使 AUC 下滑。

### 2. A800 混合概念嵌入版 (服务器第2版)
- **测试时间 (北京时间 CST)**：2026-06-20 23:24 (对应服务器 15:24 UTC)
- **备份权重**：`best_model_v6.pth.bak` (创建于北京时间 22:26，大小 36.3MB)
- **核心改进**：
  - 重构 CBM 为混合概念嵌入模型（CEM），利用 Shannon 信息熵动态门控潜残差支路。
  - 引入自适应不平衡边际损失（AIM）自适应调节正负样本分类边界。
- **实测成绩**：Dice `82.95%` | AUC `77.55%` | F1 `81.97%`
- **代码状态审计**：
  - 报告中宣称“部署了推理期后验门控审核（Post-hoc Audit Gate）以软下调打分”，但实际上 `evaluate.py` 与 `predict.py` 中**根本没有**任何后验物理一致性审计相关的代码实现。
  - `SPINHead` 虽然被引入并在 MultiTaskLoss 中被赋予了 0.001 权重的 L1 正则，但由于 `self.cbm_head.get_l1_penalty()` 在 `ConceptEmbeddingCBMHead` 中始终硬编码返回 `0.0`，导致整个 SPIN 惩罚完全为 0 且 SPIN 模块处于停用闲置状态。

### 3. A800 今日早停熔断 (当前权重状态)
- **测试时间 (北京时间 CST)**：2026-06-21 11:32 (对应服务器 03:32 UTC)
- **备份权重**：`best_model.pth.old.bak` (备份于北京时间 08:56，大小 36.3MB) / `best_model.pth` (当前覆盖权重)
- **核心现象**：
  - 触发早期停止（Early Stopping）机制，在第 31 轮训练时即自动熔断退出，未能在 Holdout 测试集上完成完整评测。
  - 目前服务器上的最佳权重文件 `checkpoints/best_model.pth` 已被该半成品模型覆盖。
- **实测成绩**（未跑 Holdout 评测）：
  - 仅验证集指标: Val Dice `78.70%` \| Val Acc `77.80%` (未跑 Holdout 评测)

- **状态与结果**：Holdout 测试集评估完成。Dice `83.11%` | **AUC 58.99% (严重退化)** | F1 `81.28%`。

- **失败成因**：DataLoader 加载验证集时，由于相对路径配置错误，抛出 `FileNotFoundError: Image not found at data/val/sample_0000/image.png`，刚启动即崩溃异常退出。
