# 云端操作手册 · 测评容器（推理服务）

> **给云端 agent 的执行手册。** 目标：在官方容器里把推理服务跑起来，让平台探针能探到、
> `/call` 能收任务、结果落到平台要求的位置。
> **不自建镜像** —— 直接用官方基础镜像 `pytorch:2.8.0-cuda12.8-cudnn9-runtime`。
> 本地 `Dockerfile` 仅供 CI 冒烟，**云上不用它**。

---

## 0. 一句话

```
python -m src.service.app     # 常驻前台进程，uvicorn 监听 8000
```

这不是"跑一次就退出"的脚本，是**常驻 HTTP 服务**。进程退出 = 评测失败。

---

## 1. 服务契约（官方规范硬要求，实现已逐条对齐）

| 官方要求 | 我方实现 |
|---|---|
| `GET /health` 返 200，端口 **8000** | `app.py::health()`，只读内存计数，不碰模型/磁盘 |
| `POST /call` **5 秒内**返回 200 | 只解析入参 + 丢线程池，不等推理 |
| 异步执行 | `tasks.submit_inference` → ThreadPoolExecutor（**worker=1**，串行） |
| 跑完回调 | `tasks.post_callback`，含指数退避重试（2+4+8s） |
| 前台长进程 | `uvicorn.run` 阻塞前台 |

**探针节奏**：启动探针 5s/次最长 1800s；探活 30s/次，**连续失败 3 次即重启容器**。
→ 所以 `/health` 必须极轻，任何阻塞都可能触发重启、整场评测作废。

## 3. 权重（最高危项）

### 🔴 必须确认加载的权重含「训好的四头」

```bash
export AICOMP_WEIGHTS=/path/to/official_heads_seg_best.pth
```

**为什么这是最高危项**：`runner.py` 的缺省权重是 `checkpoints/thyroidxl_merged_v2.pth`，
它是 ThyroidXL 分割融合权重，**位置/ETE/临床T/TI-RADS 四头在里面是随机初始化的**。

2026-08-17 起四头已接进生产 `prediction.json`（backlog #116b），所以：

- 接线**前**：四项是确定性占位（ETE 恒 1 / Location 均匀 / T 恒 0）
- 接线**后**：四项直接输出模型值 → **加载错权重 = 往 JSON 里写随机数**，
  **比接线前更糟**（占位至少确定，随机会毒化加权 Kappa）

### 自检判据（跑分后立刻看）

打开任意一份产出的 `prediction.json`，看第一个结节：

| 判据 | 说明 |
|---|---|
| 🔴 **`LocationProbs` 是不是均匀分布**（7 个 ≈0.1428） | **均匀 = 四头没接上**。这是最可靠的单条判据，与预测质量无关 |
| `ExtrathyroidalExtension` 是否恒为 1、`T_ClinSig.T` 恒为 0 | 全病例都一样 = 占位没换掉 |
| `TI_RADS_Probs` / `ETE_Probs` 两个键存不存在 | 存在说明 #116a 对冲键生效 |

同一张图连跑两次，四项输出应完全一致（不一致 = 权重没加载，走了随机初始化）。

## 4. 环境变量

| 变量 | 缺省 | 说明 |
|---|---|---|
| `AICOMP_WEIGHTS` | `checkpoints/thyroidxl_merged_v2.pth` | 🔴 **必须覆盖**，见 §3 |
| `AICOMP_CONFIG` | `configs/thyroid_config.yaml` | 一般不用改 |
| `AICOMP_PRECISION` | `fp16` | 推理 batch 恒 1，32G 显存绰绰有余 |
| `AICOMP_MAX_FRAMES` | `32` | 动态图均匀抽样上限，`<=0` 取全帧 |
| `AICOMP_WORKSPACE` | `/2026aicompetition/workspace` | 平台挂载点 |
| `AICOMP_ANSWER_ROOT` | `{workspace}/answer` | 结果根目录 |
| `AICOMP_CALLBACK_BASE_URL` | `http://10.1.13.241:80` | 平台内网网关 |
| `AICOMP_INFERENCE_WORKERS` | `1` | 🔴 **必须为 1**，模型非线程安全 |
| `PRODUCTION` | 未设 | 设为 `1` 则权重缺失时**启动即硬报错**（交付时应设） |

## 5. 启动步骤


## 6. 产出物自检

每个病例目录应有：

```
{PatientId}/prediction.json
{PatientId}/{SeriesUid 或 AccessionNumber}/nodule_001.nii.gz
```

**逐条核对**（违反任一条 → 该病例所有指标不予计分）：

- `StudyUID` 字段的值 == **PatientId**（反直觉但官方明文要求）
- `MaskFiles` 与 `Nodules[].MaskFile` **一一对应**（集合相同、数量相同、不重复）
- mask 路径是**相对路径 + 正斜杠**，无绝对路径、无 `../`
- mask 尺寸 == 原图 H×W
- **动态 3D NIfTI 的 z 轴帧数 == 原视频总帧数**（我们抽样 32 帧后会 scatter 回填，
  未抽中帧填全 0 —— 官方明确说填 0 不算违规，但**帧数不对就整例清零**）
- 阴性病例：`MaskFiles: []` + `Nodules: []`，仍要写 `prediction.json`

快速检查一份：

```bash
python - <<'EOF'
import json, glob, os
for p in sorted(glob.glob("<answer_root>/*/prediction.json"))[:3]:
    d = json.load(open(p, encoding="utf-8"))
    ns = d["Prediction"]["Nodules"]
    print(f"\n{p}  StudyUID={d['StudyUID']}  结节数={len(ns)}")
    if ns:
        n = ns[0]
        lp = n["LocationProbs"]
        uni = abs(max(lp) - 1/7) < 1e-6
        print(f"  Location={n['Location']} ETE={n['ExtrathyroidalExtension']} "
              f"TIRADS={n['TI_RADS_Class']} T={n['T_ClinSig']['T']}")
        print(f"  LocationProbs 均匀? {uni}  <- True 说明四头没接上!")
        print(f"  对冲键: TI_RADS_Probs={'有' if 'TI_RADS_Probs' in n else '无'} "
              f"ETE_Probs={'有' if 'ETE_Probs' in n else '无'}")
    assert sorted(d["Prediction"]["MaskFiles"]) == sorted(x["MaskFile"] for x in ns), "MaskFiles 不一致"
EOF
```

## 7. 运维铁律（都是踩过的坑）

1. **`nohup` + `python -u`** —— 不加 `nohup` 会被 SIGHUP 杀掉（曾跑到 ep5 断）；
   不加 `-u` 时 stdout 块缓冲，日志攒着不刷新看不到实时状态。
2. 🔴 **上传代码用 `unzip -o`，不要走"替换同名目录"** —— 2026-08-17 事故：
   人工替换目录导致 `src/models`、`src/utils`、`src/gatekeeper`、`src/inference`
   **全被抹掉**（67 个 `.py` 只剩 9 个），而 `sha256sum -c` **9 行全 OK 查不出来**
   （哈希只验列出的文件，覆盖不到被连带删除的）。
   → 核验必须加两条正交判据：
   ```bash
   find . -name "*.py" | wc -l                        # 期望 ≈69
   python -c "import src.models.multi_task_model"     # 能 import 才算真的在
   ```
3. **日志是追加不是覆盖** —— 新一轮前先 `mv` 走旧的（用 `mv` 不用 `rm`，云端产物导不出来）。
4. **判进程死活**看日志时间戳 + `nvidia-smi`，不看 `ps` 的 RSS。

## 8. 常见故障对照

| 现象 | 原因 | 处置 |
|---|---|---|
| `/health` 不通 | 进程没起来 / 端口被占 | 看 `service.log`；`netstat -tlnp \| grep 8000` |
| 每个病例都 FAILED，但 `/health` 仍 200 | 权重加载失败（`build_model` 抛错被吞成病例级 FAILED） | 查 `AICOMP_WEIGHTS` 路径；这是已知的"伪装健康跑零分"，backlog #115/#123 |
| `LocationProbs` 全是 0.1428 | 四头是随机权重或没接上 | 换成含四头的权重，见 §3 |
| 平台等不到回调 | `AICOMP_CALLBACK_BASE_URL` 配错/不通 | 看日志里的回调重试记录 |
| 容器被反复重启 | `/health` 探活连续失败 3 次 | 检查是否有阻塞操作拖住了 event loop |
| 某个病例报 gzip 错 | 输入 NIfTI 损坏（训练集实测 339 个里有 1 个） | 已知问题 backlog #126，容错降级待做 |

## 9. 与训练的关系

**推理服务和训练是两回事，不要混**：

- 训练：`python -u scripts/train_official.py ...`，产出 `checkpoints/*.pth`
- 推理服务：`python -m src.service.app`，消费训练产出的权重

跑分用的是**训练产出的权重 + 推理服务**。改了推理代码不需要重训；
改了模型结构/损失才需要重训。
