## 五、资源区（按平台 32G 显存 / 64G 内存复核，2026-08-12 实测定稿口径）

> 本地 A800 80G 不算数。推理 batch 恒 1、单帧 512² FP16，32G 显存余量更大；风险在**动态全帧 + 高分辨率长视频的 RAM 峰值**与**批量规模 vs 平台超时**。

- [ ] **32G 显存下批量推理不 OOM**。为什么：平台每容器显存 32G（2026-08-12 容器内 `nvidia-smi` 实测），本地 A800 80G 不代表平台不 OOM。怎么验证：云端首跑 100+ 病例批量，`nvidia-smi` 观察峰值显存 < 32G。
- [ ] **动态全帧（`AICOMP_MAX_FRAMES<=0`）+ 高分辨率长视频 RAM 峰值 < 64G**。为什么：`load_nifti_frames` 整体积读 CPU + `binary_3d/soft_3d` 全帧 3D 数组，2048² 500 帧单病例峰值≈12.6GB。怎么验证：云端 `free -g` 观察水位，或对长视频显式设 `AICOMP_MAX_FRAMES`（默认 32）抽样规避。
- [ ] **单批批量推理时长 < 平台评测超时**。为什么：回调在**整批跑完后**才发，批量过大 = 回调迟迟不到 → 平台判超时；worker=1 串行下任务只排队不阻塞探针。怎么验证：云端首跑记录单批耗时，超时考虑拆批。

## 六、输出契约区

> 官方硬约束：① 所有分类/分级/分型**必须输出概率分布，否则计 0 分**（🔴 TI-RADS/ETE 在 V2.1 schema 无概率字段位,已用零成本对冲键方案应对,见 `docs/待官方答复清单.md` Q4 与总纲 §7 backlog #116a）;② 动态 mask 必须 `.nii/.nii.gz`;③ 新增 ETE 4 级分级 / 7 类病灶位置 / T 临床显著性三维度(类别定义已由我方从官方数据实测得出,与评审规则编码表一致,见总纲 §4)。

- [ ] **所有分类/分级/分型输出概率分布且和为 1**。为什么：官方新约束，只输出硬标签计 0 分。怎么验证：解析 `prediction.json` 逐结节逐属性，`LocationProbs`/ETE/T 等分布 `sum≈1`（±1e-6）。
- [ ] **`prediction.json` 结构合规**（必填字段齐全、无效病例子以结构合规占位）。为什么：`write_case_v21` 原子写 + 校验，结构不合规整例失分。怎么验证：对一批输出跑 `validate_prediction_json` 全过。
- [ ] **mask 尺寸 == 原图 H×W**。为什么：`orig_hw` 透传原图尺寸，拿 resize 后的模型输入尺寸冒充会让 mask 与原图不符 → 官方判尺寸不一致整例失分。怎么验证：对比 `prediction.json` 的 mask 维度与输入图维度。
- [ ] **输出路径无 `../`、无绝对路径逃逸**。为什么：病例目录 `{output_dir}/{patient_id}`，PatientId 若含 `../` 会写出 answer 根目录、平台找不到。怎么验证：批量输出后 `find` 检查所有路径均在 `ANSWER_ROOT` 内。
- [ ] 🔴 **交付权重不是「混训产物」**（`best_model_mixtrain_xl_e40.pth` 及其后续 Stage2/3 续训物）。为什么：混训模式（`--mix-thyroidxl`）下**两源的概念标签全被屏蔽** —— TN3K 的 5 概念是 mask 反推伪标签，源级 `label_mask` 压 0；ThyroidXL 根本没有概念标注。于是概念分支参数虽 `requires_grad=True` 但**梯度恒 0，从未受过任何监督**。拿这种 checkpoint 输出 `concept_probabilities` / CBM 报告，得到的是随机初始化经 softmax 后的 **confident 垃圾**——而官方要求"必须输出概率分布"，等于把送分项做成 0 分，且报告的可解释性完全是假的。**它只适合当分割 warm-start 底座，分类/概念必须靠官方数据重训。** 怎么验证：核对交付权重文件名与 `docs/训练与架构/三头实现记录.md` §6 的权重归档记录；若确需用混训权重出分割，则 `prediction.json` 中概念/分类字段必须来自另一个受过监督的 checkpoint。（背景见 `src/training/stages.py` 的 Stage1 docstring。）
