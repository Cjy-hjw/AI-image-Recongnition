### 🔴 Q4 TI-RADS 与 ETE 的概率字段"结构性矛盾" — 仍未解决,此前"已厘清"是本会话的方向性误判,已撤销纠正

**2026-08-12 第一次判定**：评审规则字段表证实概率位分配"跟评审指标类型对齐"（Kappa不需要、AUC才需要），据此判定矛盾已厘清、撤销零成本对冲。

**同日复核后撤销该判定**：这个"评分方法学决定字段设计"的说法**是本会话自己的推理，官方原文没有一句话支持它**。评审规则「输出强制要求」原文是**无条件全称句**——「所有分类、分级、分型任务，模型必须输出各类别概率分布/置信度，无概率输出对应子任务计0分」，字面没有为任何指标类型开例外。字段表不对称（TI-RADS/ETE 无概率位，其余三项都有）恰恰是**矛盾仍在**的形态，不是被厘清的证据。

**这是与本文档 §三 记录的上一次误判同方向的重复错误**：遇到官方口径疑似冲突时，本会话又一次挑了对自己有利（少做事）的一侧当结论，只是这次包装成了更完整的方法学推理，看起来更有说服力，但本质仍是"用我方推理代替官方原文的空白"。

**结论：恢复原判定，恢复零成本对冲方案**——按 schema 填 int 的同时额外写 `TI_RADS_Probs`/`ETE_Probs`。

🔴 **2026-08-17 再次修正理由①，并降低预期收益**（原写"① 加了不违反任何明文禁令；② 若官方读 → 拿到概率分"）。本轮首次逐字读原文（此前一直读转述），发现**遗漏了一条官方正面强制要求**：

> 评审规则 `:251`（赛道七章节内，199-389 行）：「各分类任务均要求输出概率向量或置信度，**概率向量的键名必须与下表中的键名完全一致（大小写敏感）**。参赛队伍应确保输出的键名与下表完全匹配。」

而下表里 ETE 明文写着「**该字段类型为整数（int）**」（`:284-300`），TI-RADS 同理；**同时**位置那项专门配了 `LocationProbs` 概率键并逐行规定索引顺序（`:325-340`）。

→ **矛盾比原先认识的更尖锐**：官方在同一张表里给位置配概率键、给 ETE/TI-RADS 只给 int，**同时** `:185` 又是「所有分类必须输出概率否则计0分」的无条件全称句。这不是"没说清"，是**两条明文互相打架**，且「该字段类型为整数」说明官方**有意**只要 int，不是遗漏。

**修正后的理由**：
- ① 官方**无**"不得包含额外字段"条款（赛道八 `:540` 有"不得包含"，赛道七全文无对应条款）→ 加了**不会被判违规**
- ② 但 `:251` 有**正面强制**「概率向量键名必须与下表完全一致」，而表里 ETE/TI-RADS **没有概率键** → 我们自拟的 `TI_RADS_Probs`/`ETE_Probs` **必然满足不了这条**
- ③ → **拿分概率接近 0，这是纯防御性下注**，不是"官方读则拿分"。净收益仍 ≥0（int 字段照常合规、零损失），**故仍然做，但不要指望它得分**

⚠️ **方法论教训**：本条的原理由只问了"**有没有禁令**"，没问"**有没有正面强制要求**"。**禁令缺席 ≠ 被允许** —— 判断某做法是否可行时两者都要查。

**能否自测**：🔴 完全不能，这是评分脚本行为。若仍存疑，建议向官方发一条简短确认（"TI-RADS/ETE 是否需要在 int 之外再输出置信度字段"）。

**落地状态**：🟢 **backlog #116b 已于 2026-08-17 完成落地**（此前一直是"已定稿但从未落地代码"）。`build_nodule_entry` 新增可选参数 `tirads_probs`（5维）/`ete_probs`（4维），写出 `TI_RADS_Probs`/`ETE_Probs`；`None` 时**不写该键**（旧调用方零污染）；长度错即抛 `PredictionSchemaError`（长度错 = 上游取错了头）。输出的是**训练好的头的真实概率**，不是占位。测试从 `write_case_v21` 入口验到落盘 JSON —— 只测单函数会漏掉"调用处没透传"这一步（参数加了、写出逻辑也有，但调用处不传则键静默消失，而 `validate_prediction_json` 只查缺失不查多余、不报错）。
