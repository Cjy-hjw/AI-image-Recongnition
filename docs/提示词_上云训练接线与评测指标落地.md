## 1. 官方评分口径（逐条核对官方原文，不要凭印象）

读 `docs/8.1赛事公开资料/初赛评审规则简要说明.md` 时重点核对这几件事，因为本会话之前在这些点上出过方向性误判：

| 项 | 官方原文位置 | 易错点 |
|---|---|---|
| 总分公式 | 「初赛完整计分规则」第2条 | **总分 = Sclin，无 ×100**（Sclin∈[0,1]）。别把07-28动员会旧口径"×100"当现状。 |
| Sclin 构成 | 赛道七§1/§2 | 目标三(检出肿瘤/非肿瘤)60% + 目标四(恶性结节分期)40%，目标五(可解释性)初赛不计分。**60%/40%内部各子任务如何再分配未知**，这是唯一剩余盲区。 |
| 各子任务指标 | 赛道七§1(1)(2)、§2(1)(2)(3) | 良恶性=**AUC-PR**（不是AUC，也不是Macro-AUC）；TI-RADS=**加权Kappa**；ETE=**侵犯分级加权Kappa，仅匹配成功且为恶性的主病灶**；位置=**位置分类加权宏平均AUC，仅匹配成功的主病灶（不限恶性！）**；T=**T分级临床显著性AUC，仅匹配成功且为恶性的主病灶**。 |

| 主病灶匹配 | 「赛道七」正文第2段 | 静态=2D掩膜IoU；动态=各标注帧帧级IoU算术平均；均用**匈牙利算法一对一最优匹配**，**IoU≥0.5判定成功**。漏检的主病灶不参与分类/分期指标，但已在检测AP+Dice里受双重惩罚。 |
| 概率输出强制 | 「输出强制要求」 | 无条件全称句："所有分类、分级、分型任务，模型必须输出各类别概率分布/置信度，无概率输出对应子任务计0分"。**字面没有为任何指标类型开例外**。 |

## 2. 数据格式要点（核对 `训练数据定稿.md`，不要凭印象猜字段）

- 目录层级：一级=PatientId(32位hex)；二级=SeriesUid(静态)或PatientId同名嵌套(动态)。
- 静动判据：`.dcm`=静，`.nii.gz`=动，全量互斥0混合，按扩展名分发。⚠️ **该文件§1.3与§4.2的具体数字口径存在未查明的不自洽**（4680+721=5401 但 5057+343=5400，且与6361个子目录不在同一量级），2026-08-12审查已标注但未解决，**训练接线时不依赖这几个具体数字，只依赖"互斥、按扩展名分发"这个结论**（该结论本身有三方交叉验证，可信）。
- 编码表（`src/models/label_schema.py` 权威，**训练侧构造标签必须 import 这里的常量，禁自定义映射**）：
  - 位置 `LOCATION_LABELS`：1左上 2左中 3左下 4右上 5右中 6右下 7峡部（7类，与旧格式说明文档"9类"矛盾，按此7类为准）。
  - 侵犯 `ETE_IDX_TO_CODE`：1无 2包膜 3软组织 4血管（4类，阴性/NA/UNK入码1）。
- masked loss 判据 = **该临床列是否为空**（非"是否M行"）：非主病灶(病灶N)也有约13%带临床标注，逐行检查该列有值就回传、空就skip。
- 防泄漏铁律：`GroupKFold(groups=一级目录名=PatientId)`，禁随机KFold/train_test_split。

## 3. 阶段2.4：训练循环接线要做什么

现状（`src/training/trainer.py`）：`train_epoch`/`validate_epoch` 只处理分割Dice + 良恶性AUC（`roc_auc_score`），**完全没有三头（位置/ETE/临床T）的损失接入与验证指标**。`validate_batch`（`src/training/loop/validate_step.py`）的 `targets` dict 里也没有三头对应键。

**要接的东西**：
1. **数据侧**：`official_loader.py` 已经把 `lesion_loc`/`extrathy_ext`/`clin_t_stage` + 各自 `valid_{task}` 放进了 `labels` dict（`src/dataset/official_loader.py:268-295`），但这是**官方数据**专用加载器，**从未在真实官方数据上跑过**（本地无数据，只能云上验，见 §5 硬前置①）。
2. **损失侧**：`src/models/losses/multitask.py::forward` 目前只吃 `targets['mask']`/`composition`/`echogenicity`/`shape`/`margin`/`foci`/`malignancy`，**没有位置/ETE/T的分支**。需要新增三头各自的 `losses/components/{location,extension,clinical_t}.py`（这三个文件其实已存在且被三头模块各自 import，但**主 `multitask.py` 的顶层 criterion 尚未把它们编排进联合损失**）。
3. **验证侧**：`validate_epoch`/`validate_batch` 需要新增三头各自的验证指标计算，且**必须按 §1 表格里的官方口径复现**（尤其"位置不限恶性、ETE/T限恶性"这条筛选逻辑，否则本地验证数字与官方评分口径系统性对不上）。
4. **主病灶筛选逻辑**：`official_loader` 当前对 `病灶N`（次病灶）也建样本，三头的损失加权与验证指标**必须只按主病灶(RoiName=M)统计**——官方评分口径明确"仅匹配成功的主病灶"参与ETE/位置/T指标。这条尚未在训练侧任何地方实现，是2.4接线的核心工作之一。
5. **调度**：**禁止复用 `src/training/stages.py::configure_stage_parameters`**——那套三阶段划分（Stage1→2有100倍lr跳变）是历史遗留、已实测导致分割崩塌（总纲§6有完整故障记录），官方数据训练需要**另建一套A/B/C调度**（Ep1-10冻主干温升新头 → Ep11-30 LLRD解冻Top-2 → Ep31-35概率校准）。

**验收标准**（写完后必过）：
- `verify_model.py` Gate1 全绿。
- Gate2（该改动触及损失数学/梯度路由，**必须**逐头派reviewer子agent审查，禁haiku）。
- 用**合成/mock标签**在阶段3（公开集联调）先跑通forward/backward/masked loss数值健康，再上云用真实标签验证。

## 4. 三头概率导出契约（呼应官方"无概率计0分"）

`src/inference/v21_output.py` 当前的三新维度输出仍是**占位**（ETE=1恒定、Location均匀分布、T=0），backlog `#116` 未闭环。接线时同步做：
- `LocationProbs[7]`（和=1，`compose_location_probs` 已实现，位置头本身产出正确分布，只是没接到 `prediction.json`）。
- ETE 4类概率 + 官方要求的 `TI_RADS_Probs`/`ETE_Probs` 对冲字段（§1表格最后一条）。
- T 二类置信度（`T_conf = P(T=1)`，**不是**"对所报T值的置信度"，`ClinicalTOutputs.t_conf` 已按此语义实现，见 `src/models/heads/__init__.py` 顶部docstring）。

🔴 **不要在三头训练完成前就接生产路径**：随机初始化的输出比占位更危险（占位是"明确有偏"，随机初始化"看起来像真的"）。接线顺序是：**先训练验证损失/指标数值健康 → 上云真训 → 权重就位后再接 `v21_output.py`**。
