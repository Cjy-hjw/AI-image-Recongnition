### 3.1 比赛与评分口径(官方原文,不可臆测)

- 赛道:甲状腺超声癌症智能检测,**自有模型组**,交付物 = 容器化常驻 HTTP 推理服务。
- 总分 = Sclin = **目标三(检出肿瘤/非肿瘤)60% + 目标四(恶性结节分期)40%**。
- 各子项与我方当前线上得分(满分由分项拆解反推,四项验算与官方公布的得分率逐位吻合):

| 子项 | 指标 | 满分 | 当前得分 | 得分率 |
|---|---|---|---|---|
| 结节分割 | **单个结节平均 Dice**(对所有金标准结节,匹配成功取实际 Dice,**未匹配取 0**,取平均) | 15 | 8.72 | 58% |
| 结节检测 | **结节检测 AP**(所有预测结节参与,标签由匹配结果决定) | 15 | 9.33 | 62% |
| 良恶性 | AUC-PR,仅匹配成功的主病灶 | 18 | 16.22 | 90% |
| TI-RADS | 加权 Kappa,仅匹配成功的主病灶 | 12 | 8.32 | 69% |
| 甲状腺外侵犯 ETE | 加权 Kappa,仅匹配成功且为恶性的主病灶 | 13.33 | 7.52 | 56% |
| 主病灶位置(7类) | 加权宏平均 AUC,仅匹配成功的主病灶 | 13.33 | 9.36 | 70% |
| T 临床显著性 | AUC,仅匹配成功且为恶性的主病灶 | 13.33 | 9.15 | 69% |
| **合计** | | **100** | **68.80** | |

- **匹配规则(决定一切)**:
  - 静态:预测实例与金标准病灶的 **2D 掩膜 IoU**;
  - 动态:**各标注帧帧级 IoU 的算术平均**;**若某标注帧上模型无预测(切片为空或全0),该帧 IoU 记 0**;不设单帧 IoU 下限;
  - 均用 **匈牙利算法一对一最优匹配**,**IoU ≥ 0.5 判定匹配成功**;
  - 漏检的主病灶:分类/分期五项不参与计算(不贡献样本),但在 **检测 AP(召回下降)与单结节平均 Dice(记 0)中受双重惩罚**。
- **置信度规范**:`Detection.confidence` / `Malignancy.confidence` / `T_conf` 值域 [0,1];缺失、NaN、Inf、类型错误、越界 → 该置信度按 0 处理,该样本在所有排序类指标(AP / AUC-PR / AUC)中**排在最后**。
- **窗口约束**:初赛 09-30 截止,今天 09-17,**剩 13 天**。每天有 **5 次线上跑分机会**,但**最终模型只能提交一次**,提交后不可更换,禁止联网,权重不可导出。

### 3.2 数据形态(全量实测)

- 样本总数 **6626** = 静态 **5459** + 动态 **1167**;动态病灶数 339,平均 **3.44 个标注帧/病灶**(官方只标注开始帧/清晰帧/结束帧,其余帧无标注)。
- 按 **case(病例)** 口径:验证池 1042 case = **静态 993(95.3%) + 动态 49(4.7%)**。用样本数反推全量自洽(1167 ÷ 4.8 帧 ≈ 243 动态 case;5459 ÷ 1.1 ≈ 4965 静态 case)。**测试集同源,比例应一致——这意味着动态池最多只值总分的约 0.4 分,请在收益估算中据此加权。**
- 静态:DICOM 单帧灰度,图幅跨度约 6.5 倍(约 300k ~ 2M 像素)。动态:NIfTI cine 序列,3~750 帧。
- 病灶尺度:金标准病灶占图幅面积比的中位数约 **1.55%**,四分位 0.54% ~ 4.68%;漏检病灶里有大量 0.03% ~ 1% 的极小目标。按 512×512 输入折算,中位病灶约 63×63 像素,小病灶低至 10×10 像素。
- **标注只有掩膜,没有边界框**;主病灶(RoiName=M)有全部 5 个临床属性,次病灶只有掩膜。主病灶与次病灶数量比约 1 : 0.25。
- 患者级防泄漏:所有划分按 PatientId 分组。

### 3.3 现有模型架构(被替换的对象)

- **双骨干,24M 参数,输入 512×512,单通道灰度(in_chans=1,不是 3 通道)**:
  - 分割骨干 `convnext_nano`(timm,features_only,out_indices 0-3,stride 4/8/16/32,LayerNorm,无 BN);
  - 分类骨干 `efficientnet_b2`(timm,BatchNorm,约 69 个 BN 层)。
- **分割解码器**:U-Net 式,五级 ConvTranspose(512→320→160→80→40→20),前三级 concat 跳连,最后 1×1 Conv 出单通道 logits。**输出即 512×512 全分辨率,无 F.interpolate 上采样,无 deep supervision。**
- **五个分类头**:输入统一是分类骨干 stage4 空间特征 `[B,352,16,16]` + detach 的软分割掩膜 + 概念瓶颈模型(CBM)的 margin + 结节尺度标量;**全部经 adaptive average pooling,与输入分辨率无关**。
- **分割损失**:`BCEWithLogitsLoss()`(**无 pos_weight**)+ 标准对称 soft-Dice,**等权直接相加**。全仓无 Tversky / Focal-Tversky / 任何 FN 与 FP 不对称加权,**也没有按病灶实例归一化的 per-lesion 损失**(损失是整图像素级的,而官方指标是单结节平均——每个结节等权)。另有 Boundary / Lovász 两项可选外挂(已试过,见 §5.1)。
- **检测是"分割式检测"**:没有检测头。实例 = 二值化后的连通域;`Detection.confidence` = **该实例区域内 sigmoid 概率的算术均值**;动态实例的置信度 = 该实例出现的各帧逐帧概率均值再平均。
- 推理:fp16,batch=1(动态帧内部按 batch 8 批量前向,OOM 时对半降级重试)。

### 3.4 训练与验证现状(重要:判据有缺陷)

- 训练环境:云端 RTX 5090,35 epoch ≈ 55 分钟,显存 8.7GB / 32GB。
- **当前的选模判据与官方评分口径是脱钩的**(已代码核实):
  - 训练里的 `val_dice` = **整图像素级 hard Dice 逐样本平均**,金标准掩膜直接喂入,**没有 IoU 匹配、没有实例聚合、漏检不记 0**;
  - 选模标量 `composite` = 最多 6 项(5 个分类指标 + val_dice)**等权算术平均**,**里面没有检测 AP**;
  - 训练/验证循环**完全不计算**官方口径的匹配率、per-lesion Dice、AP;
  - 更糟:`val_dice` 的分母是**样本数**,动态样本按**帧**计权,导致动态在选模判据里占约 17.6% 权重,而它在官方分里只值 4.7%,**系统性过权 3.7 倍**。
- 我方已有一个独立的离线诊断脚本,可直接吃任意 `.pth` 权重、自己跑前向,产出**官方口径**的匹配率 / per-lesion Dice(未匹配计 0)/ AP。**新架构的验证将使用这套口径,不再用 val_dice。** 调研时请假定我方有能力对任何候选做官方口径的离线评估。

### 3.5 落盘契约(唯一不可变的部分,候选必须能对接)

这是 5 次线上零分事故换来的防线,已有 66 项端到端验收测试。**任何候选方案的输出必须能塞进这套契约:**

1. 逐病例输出 `{PatientId}/prediction.json` + **逐结节一个 `.nii.gz` 掩膜文件**。
2. `MaskFiles` 列表与 `Nodules[].MaskFile` 必须**一一对应**(集合完全相同、数量相同、不得重复、不得用绝对路径或 `../`),违反即该病例所有指标不予计分。
3. **静态掩膜必须写成 3D 带单帧 `(W, H, 1)`**,写纯 2D 会被官方 shape 校验整批判零(此坑官方文档无记载,我方踩过)。
4. **动态必须输出包含完整视频全部帧的 3D NIfTI**,z 轴切片总数与帧顺序必须与原视频完全一致;多一帧少一帧或时序错乱 = 格式错误,该病例所有指标不予计分。无结节的帧填全 0 合法。**这就是为什么动态不能抽样、必须全帧前向。**
5. 预测目录**白名单**:只允许 `.nii` / `.nii.gz` / `.json`,混入任何其他文件(我方曾误写匿名化 `.dcm` 副本)= 整批判零。
6. 每个检出结节都必须输出**完整的属性字段**(良恶性概率、TI-RADS 等级、ETE 编码、7 类位置概率向量、T 分级与置信度),评估脚本自动按空间匹配结果挑出主病灶来评分,**模型无需显式标记哪个是主病灶**。
7. 所有分类/分级/分型**必须输出概率分布或置信度,否则该项计 0 分**。

**推论给调研者**:候选架构必须能产出 (a) 实例级二值掩膜,(b) 每实例一个 [0,1] 置信度,(c) 每实例 5 组分类/分级输出。真检测器(输出框)如果不能同时产出像素级实例掩膜,必须说明如何补掩膜分支;纯语义分割方案必须说明如何切分实例。

## 四、失血归因实测数据(这是你的筛选靶子,请逐条对照)

以下全部是云端全量诊断的实测数字,不是估计。**任何候选的"为什么适配"论证都必须指向这里的某一条。**

### 4.1 分数缺口的分布

- **Dice(15 分)+ AP(15 分)合计 30 分,现得 18.05,缺口 11.95 分。这是全场唯一有量级的矿。**
- 其余五项合计 70 分现得 50.75,缺口里良恶性只剩 1.78 分(得分率已 90%),TI-RADS/位置/T 各剩 3~4 分但全是分类头的活、与架构级更换的关系弱。
- **结论:架构更换的价值必须体现在 Dice 与 AP 上,否则不值得做。**

### 4.2 静态池(95% 分值占比)——失血全在召回,不在边界质量

- 993 个 case,约 **1119 个金标准病灶**,匹配成功 **919 个,匹配率 0.8213**,AP **0.7927**,平均 Dice 0.73(= 0.8213 × 已匹配平均 Dice)。
- **已匹配病灶的 IoU 分布:p25 = 0.746 / p50 = 0.837 / p75 = 0.888**(IoU 0.837 对应 Dice ≈ 0.91)。
  → **这是成功匹配后的条件统计**:支持"追召回优先于追边界"的战略排序,**不能**独立量化全部边界收益(它不描述匹配长尾,也不描述漏检病灶的潜在边界空间)。
- **漏检 200 个病灶**,拆成两组:
  - **近失 61 个**:最大 IoU 落在 [0.35, 0.50),差一点过线;
  - **远失 139 个**:最大 IoU < 0.35(含完全没有任何重叠的);
- **关键实测(有范围)**:近失的病灶面积比中位数 **0.0175**,比已匹配病灶的中位数 0.0155 **还大 → "近失整体是小目标"这个假设不成立**。但它**不能**否定:远失 139 个里的小病灶、低面积尾部、细长形状、或下采样后的有效尺度问题——这些仍需候选方自行论证。
- **第二个关键实测(有范围)**:我方做过双阈值滞回区域生长(高阈值定种子 + 低阈值长轮廓 + 只保留含种子的连通域)的三档网格扫参,结果是已匹配实例的边缘全部描粗(Dice +0.4pt、AP +0.3pt),但 **61 个近失一个都没救回,匹配率三点纹丝不动**。
  → 这证明的是**"已测试的这一种后处理机制(thr/grow 组合)对近失无效"**,不构成"一切阈值/形态学/后处理手段都无效"的机制定理。候选若主张其他形态的分数校准、局部阈值或实例分离手段,需要给出与已试机制的可区分理由。
- **🔴 漏检机制账(必答,新增)**:上面两个实测只描述了漏检的"结果"(max IoU 分布),**没有区分漏检的"机制"**。只看每个 GT 的最大 IoU 无法区分以下五种情况,而它们对应完全不同的架构选择:
  1. 有软概率响应,但被阈值/面积过滤/实例数截断删掉;(损失或解码问题)
  2. 多个 GT 被一个预测连通域合并,一对一匹配只能保一个;(实例分离问题——实例分割对症)
  3. 一个 GT 被多个预测碎片覆盖,单个碎片都不过线;(实例聚合问题)
  4. 病灶已定位,但轮廓/尺度/位置偏差使 IoU 不过线;(形状先验或损失问题)
  5. 对应区域几乎没有响应。(表征或监督问题)
  **首攻候选必须说明它主要吃掉哪几种机制,并给出"用什么最小诊断能区分这五种"的建议**(我方可离线跑逐 GT—预测重叠关系/主次病灶分层/多单病灶病例分层统计)。对 139 个远失解释不了的候选,必须明确其收益只覆盖哪部分,不得借全部漏检估总收益。
- **这 200 个漏检里,主病灶漏检率只有 4.3%,次病灶漏检率 17.1%**(主:次数量比约 1:0.25)。次病灶只影响 Dice 与 AP,不影响分类五项。

### 4.3 动态池(4.7% 分值占比)——机制疑似"逐帧掉线"

- 49 个 case,72 个金标准病灶,匹配成功 28 个,**匹配率 0.3894**,AP **0.2140**,平均 Dice 0.28。
- **已匹配病灶的 IoU:p25 = 0.529 / p50 = 0.597 / p75 = 0.700**(远低于静态的 0.837)。
- **近失 16 个**,IoU 值聚集在 **0.39~0.43** 与 **0.48~0.52** 两簇。
- **我方的工作假说(尚未证实,请调研者据此判断候选是否对症)**:官方动态 IoU = 标注帧帧级 IoU 的算术平均,空帧记 0。若单帧分割质量与静态同档(ū ≈ 0.80),则命中 2/4 帧 = 0.40、3/5 帧 = 0.48、3/4 帧 = 0.60 —— **观测到的整数比结构与此高度吻合**。即动态的主要失血可能不是"分割质量差",而是**模型在部分标注帧上干脆输出空白**。
- 已排除的解释:"碎裂成多个预测实例再被稀释"——实测 72 个金标准里只有 1 个(1.4%)对应到 ≥2 个候选实例,所以不是碎裂。
- 已排除的解释:"抽样漏掉标注帧"——早期确有此 bug(32 帧均匀抽样导致动态 TP 归零),已修复为全帧前向,修复后 AP 从 3.05 分涨到 9.47 分。
- **动态的总分上限**:即便把动态修到完美(Dice 0.28→0.60、AP 0.21→0.50),按 4.7% case 占比折算总分只有 **+0.43 分**。请在收益估算里严格遵守这个上限,不要因为"动态相对最烂"就高估它的绝对价值。

### 4.4 由 4.2 / 4.3 导出的候选筛选靶子

一个候选值得考虑,必须至少命中下面一条,并解释机理:

- **靶 A(最大,约 +1.2~2.1 分,假设其余口径不变)**:把静态匹配率从 0.821 提到 0.88~0.90。即救回那 61 个近失 + 部分 139 个远失。两个实测(面积比/grow 零救回)指向"定位与形状先验比更高分辨率更值得押注",但这是**战略优先级判断,不是机制定理**(见 4.2 的范围声明)。
- **靶 B(约 +0.3~0.5 分)**:把已匹配病灶的 IoU 中位从 0.837 提到 0.90+。边界质量,空间较小(条件统计的局限见 4.2)。
- **靶 C(≤ +0.43 分,按 4.7% case 占比的折算,前提是测试集静动比例与训练集同源)**:动态逐帧稳定性。上限很低,除非能顺带服务靶 A。
- **靶 D(约 +0.3~0.6 分)**:检测置信度的排序质量。注意静态 AP 0.7927 / 召回上限 0.8213 = **96.5%,现有候选集的排序已接近召回天花板**;但**新架构释放新候选后不保证仍如此**——AP 的增长必须来自召回,且新候选的置信度质量本身就是待验证项(见组 4 的 FP 账问题)。
