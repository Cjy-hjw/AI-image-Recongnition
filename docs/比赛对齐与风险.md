## 二、为什么"必须先看官方数据"

比赛规则明确：**主办方统一提供数据**、**专属云环境训练**、**禁止外传/截图**。所以：

1. **基础两项(真实性/规范性)的真实标注只能来自官方** —— 真假人体、重复、拼接这些**取证样本**,公开数据集几乎没有对口的(我方现用合成引擎 `synthesis.py` 造训练数据 + CAT-Net/SSCD 预训权重打底),最终须用官方标注集验证/微调 `authenticity` 和 `tampering`。~~这是入场券,优先级最高。~~（**2026-07-28 已豁免**：赛道七无 Sins 得分，此二项不再是入场券，见文首豁免说明；仍建议投入防御性验证，但优先级低于临床诊断相关项）

2. **良恶性可先用公开数据预训、官方数据微调** —— TN3K 是纯分割集(malignancy 全 0)不能训分类;但选型报告已锁定 Stanford AIMI/Thyro-LMD(均带病理确诊良恶性),**可现在就预训出成熟分类基线**,8-01 官方数据到位后微调适配(自有模型组正是"成熟模型+微调"范式)。不再是"只能干等"。

3. **现在能做的只是"架构预演"** —— 用 TN3K + 公开数据集验证管线能跑通、不崩溃、指标能算出来。但真实性能数字要等官方数据才有意义。

### 关键未知（看到官方数据才能确认）
- 官方是否提供真假/重复/拼接的标注？标注粒度（图像级/像素级/bbox）？
- 良恶性标签形式？是否带 TI-RADS 概念级标注（决定 CBM 头能否监督训练）？
- 是否带分割 mask？分辨率、设备异质性如何？
- 数据量级、阴阳性比例？

## 风险总结

- **（旧,已豁免）最高风险**：基础两项(真实性/规范性)不达标 → 直接出局。~~当前是传统算法骨架，真实精度未知，必须用官方数据验证/升级。~~ **该判断已被 2026-07-28 官方豁免规则推翻**——赛道七无 Sins 得分，gatekeeper 不达标不影响总分排名/晋级资格。保留原文存档。
- **gatekeeper 统一软flag制度(2026-07-12 新增，P2启动前排查发现的一票否决红线风险)**：审计发现 gatekeeper 三条硬拒绝分支——`authenticity.py` 的 argmax 判定、`tampering_catnet.py` 的 CatNet↔copy_move 信任耦合、BAG 相位不一致——均存在"训练/阈值仅经合成数据验证、零真实域 FPR 实测，却直接一票否决"的风险，与此前 copy-move 27.3% 真实图误报被降级为软 flag 的先例同源。已按以下制度处理：① `authenticity.py` 分类结果降级为软 flag(仅审计,不驱动 REJECTED,不变)；权重缺失/损坏自 **2026-08-10 R3** 起在 `build_auth_module` 降级为返回 None + `auth_skipped=True`（零计分组件故障不拖垮整例诊断，较此前硬报错更优）；② copy_move/splice 与 CatNet 状态彻底解耦(不再因"CatNet 这次没崩溃"就把 27.3% 误报的几何判据升级为硬拒绝)；③ BAG 相位不一致加 `bag_hard_reject` 显式开关，默认 `False`(仅软 flag)。**统一闸门**：任何硬拒绝分支恢复"一票否决"资格，唯一条件是在官方真实干净 holdout 上完成预注册、带置信区间的 FPR 验收，不接受"加个置信度阈值"这类替代方案。详见 `docs/P2红线修复实施计划.md`、`docs/P2启动定论_Opus复核.md`、`src/gatekeeper/AGENTS.md` §1/§3。
- **（旧,已豁免）次高风险**：误以为"分类做好就行"。~~实际上分类是决赛才重点考的核心项，但进不了决赛(基础项挂)再好的分类也白搭。~~ **豁免规则出台后此风险不再成立**——赛道七总分即为临床诊断得分，分类/分级/分型质量直接决定初赛总分，无"基础项挂→进不了决赛"这一前置门槛。保留原文存档。
- **~~新增风险(2026-07-28)~~ → 已修复(2026-07-29)：概率输出不达标 → 直接计0分**：官方新约束"所有分类/分级/分型任务必须输出功率分布或置信度，否则计0分"——原 `postprocess.py::decode_predictions` 对 composition/echogenicity/shape/margin 四个 TI-RADS 概念头只取 `argmax`，完整 softmax 概率分布从未落入 `result.json`（`cbm_head.py` 内部已算出，属**导出遗漏**非能力缺失）。**修复**：`decode_predictions` 补 `comp_prob`/`echo_prob`/`shape_prob`/`margin_prob` 完整分布 + `mal_probs` 二类分布（`mal_prob` 恒等于 `mal_probs[1]`，同源）；新增 `build_probability_export()` 作为静态图/动态图**共用**的导出层，`result.json` 增 `concept_probabilities`/`concept_predicted_index`/`malignancy_probabilities`。概率与 argmax 走同一条温度校准通路，类别顺序对齐 `report_generator` 映射表与 `configs/thyroid_config.yaml` 的 `num_classes_*`。回归 `tests/test_probability_output.py`（20例，含 AST 断言两入口不得各自手写概率字段）。**注意**：CBM 五概念头仍未经语义监督（`train_thyroidxl.py` 只训 malignancy + 分割），概率数值格式达标但语义未验证，报告侧已加免责标注，待 8-01 官方概念标注重训。
