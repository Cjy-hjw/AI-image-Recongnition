## 摘要与核心结论

本报告针对甲状腺超声多任务模型（包含分割、概念、物理先验、良恶性分类、SupCon 共 5 个任务）中 FAMO（Fast Adaptive Multitask Optimization）动态损失加权模块的方向正确性进行了深入的数学推导、原论文对拍与工程核验。结合 NeurIPS 2023 原论文（Liu et al., arXiv:2306.03792）的算法规范、数值仿真实验以及内部模型退化现象，得出以下确定性结论：  

1. **当前实现存在极性颠倒（符号方向错误）**：`src/models/famo.py` 中的简化启发式公式 `delta = improvement - avg_improvement` 配合 `w_logits += beta * delta`，导致“改善快/降幅大”的强任务获得更高的线性损失权重，而“改善慢/欠优化”的弱任务权重被持续压制。这违反了代码注释宣称的“救最差任务”（maximize the worst-performing task）原则，是导致分类 AUC 退化至 0.51–0.53（分割主干强梯度支配共享表征层）的核心诱因之一。  
2. **当前启发式并非原论文 FAMO 算法**：原论文 Algorithm 1 建立在对数损失空间（Log-loss Space）**与**对数下降率（Logarithmic Rate of Improvement）之上，通过对数梯度 ∇log*L*=*L*1∇*L* 赋予小损失任务天然的放大效应。当前代码将其简化为“线性损失改善率减均值”，且在施加于线性加权损失（∑*w**i**L**i*）时未做极性反转，导致线性加权方向与原论文及救弱任务初衷完全相反。  
3. **修复与工程落地策略**：
   - **短期最小化修复**：将启发式 `delta` 符号取反，即改为 `delta = avg_improvement - improvement`（或 `w_logits -= beta * delta`）。此修改可立即实现“给改善慢的任务加权”，且与 *L*2 正则项（−*γ**w**l**o**g**i**t**s*）及 Softmax 归一化无不良侧效应。  
   - **中长期推荐方案**：鉴于 5 任务少样本（500–2000 例）及边缘算力约束，推荐直接将 `FAMOScheduler` 升级为**原论文标准 FAMO 算法**（基于对数损失标量化与对数下降率更新），以获得理论保证的 Pareto 平衡收敛性。  
   - **门禁防御**：当前测试脚本 `gate4_famo.py` 仅验证了 Logits 非 NaN 与数值变化，未能捕捉方向错误。必须补全方向性断言（Directional Assertion）测试，防止回归。  

## 一、 FAMO 原论文理论推导与算法机制解析 (Q1 深度解答)

### 1.1 原论文 FAMO 算法规范 (Algorithm 1)

根据 FAMO 原论文（Liu et al., *Fast Adaptive Multitask Optimization*, NeurIPS 2023）第 3 节及 Algorithm 1 的精确定义，FAMO 旨在解决多任务学习中的冲突梯度与不平衡优化问题，其空间与时间复杂度均保持在 O(1)。  

原论文的精确数学定义如下：  

1. **损失标量化与模型更新**： FAMO 定义在对数损失空间中。令 *L*(*θ*)=(*L*1(*θ*),…,*L**K*(*θ*))⊤∈R>0*K* 为 *K* 个任务的损失向量，稳定性偏移量为 *ϵ*=1*e*−8。定义对数损失偏移向量 Δ*t*=*L*(*θ**t*)+*ϵ*。 设任务 Logits 为 *w*∈R*K*，通过 Softmax 生成归一化权重 *z*=Softmax(*w*)∈Δ*K*。 模型参数 *θ* 的更新方向依据对数损失的加权组合：  

   *θ**t*+1←*θ**t*−*α*∇*θ*(*k*=1∑*K**z**k*log(*L**k*,*t*+*ϵ*))=*θ**t*−*α**k*=1∑*K**L**k*,*t*+*ϵ**z**k*∇*θ**L**k*,*t*

   其中，作用于任务 *k* 真实损失梯度的有效权重系数为 *c**k*=*L**k*,*t*+*ϵ**z**k*。  

2. **改善率与 Logits 更新规则**： 定义第 *k* 个任务在对数空间下的下降变化量为：  

   *v**k*(*t*)=log(*L**k*,*t*+*ϵ*)−log(*L**k*,*t*−1+*ϵ*)=log(*L**k*,*t*−1+*ϵ**L**k*,*t*+*ϵ*)

   若任务 *k* 的损失下降（改善快），则 *L**k*,*t*<*L**k*,*t*−1，此时 *v**k*(*t*)<0 且为负大数；若任务 *k* 改善慢或停滞，则 *v**k*(*t*) 接近 0 或为正数。  

   Logits 向量 *w* 的梯度 *δ*∈R*K* 定义为 Softmax 雅可比矩阵 ∇*w**z*(*w*)⊤ 与下降变化向量 *v*(*t*) 的乘积：  

   *δ*=∇*w**z*(*w*)⊤*v*(*t*)=(diag(*z*)−*z**z*⊤)*v*(*t*)=*z*⊙*v*(*t*)−*z*(*z*⊤*v*(*t*))

   具体到第 *k* 个任务分量：  

   *δ**k*=*z**k*⋅(*v**k*(*t*)−*v*ˉ(*t*)),其中 *v*ˉ(*t*)=*j*=1∑*K**z**j**v**j*(*t*)

   FAMO 原论文 Algorithm 1 中 Logits 的更新公式为（注意其中的**减号**）：  

   *w*←*w*−*β*(*δ*+*γ**w*)

   展开即为：  

   *w**k*(*t*+1)=*w**k*(*t*)−*β*⋅*z**k*⋅(*v**k*(*t*)−*v*ˉ(*t*))−*β**γ**w**k*(*t*)

### 1.2 原论文的目标与平衡机制

原论文 Section 3.1 明确指出，FAMO 的优化目标是**最大化最差任务的下降率**（Maximize the worst-case rate of loss improvement）。定义任务 *k* 的改善率为 *r**k*(*α*,*d**t*)=*L**k*,*t**L**k*,*t*−*L**k*,*t*+1≈−*α*∇log*L**k*,*t*⊤*d**t*。 FAMO 寻求更新方向 *d**t* 以求解 max*d**t*min*k**r**k*(*α*,*d**t*)。根据对偶理论，这等价于在对数损失梯度空间求解 Pareto 平衡点。  

在原论文算法中，对数损失形式 log(*L**k*) 赋予了小损失任务天然的 *L**k*1 梯度放大因子。Logits 更新公式 *w*←*w*−*β**δ* 通过对数变化量差值 (*v**k*−*v*ˉ) 动态微调权重 *z*，使得整个优化过程稳步朝着各任务**对数下降率均衡**的方向收敛。  

### 1.3 当前代码与原论文的本质差异与对拍

当前代码 `src/models/famo.py` 使用了简化启发式：

- 改善率定义：*I**k*=∣*L**k*,*t*−1∣+1*e*−4*L**k*,*t*−1−*L**k*,*t*。  
- 中心化差值：delta*k*=*I**k*−*I*ˉ。  
- 更新公式：`w_logits += beta * delta - gamma * w_logits`。  
- 加权方式：`weighted_loss = sum(losses * weights)`（直接施加于**线性损失**）。  

对比线性改善率 *I**k* 与原论文对数变化量 *v**k* 的关系：

*I**k*=*L**k*,*t*−1*L**k*,*t*−1−*L**k*,*t*=1−*L**k*,*t*−1*L**k*,*t*≈−log(*L**k*,*t*−1*L**k*,*t*)=−*v**k*

因此，*I**k*≈−*v**k*。改善快（*L**t*≪*L**t*−1）意味着 *I**k*>0（正大数），而 *v**k*<0（负大数）。  

下表展示了在包含 Task 0（改善快，损失 1.0→0.5）和 Task 1（改善慢，损失 1.0→0.95）的二任务模型中，原论文 FAMO、当前代码以及符号取反后的启发式的数值推导对比：  

| 维度 / 算法类型                | 原论文 FAMO (NeurIPS 2023 Alg 1)          | 当前实现 (`src/models/famo.py`)  | 符号取反启发式 (`avg - imp`)         |
| ------------------------------ | ----------------------------------------- | -------------------------------- | ------------------------------------ |
| **损失空间与加权**             | 对数损失 ∑*z**k*log*L**k*                 | 线性损失 ∑*w**k**L**k*           | 线性损失 ∑*w**k**L**k*               |
| **改善量度 (\*k\*=0/\*k\*=1)** | *v*=[−0.6931,−0.0513]                     | *I*=[+0.5000,+0.0500]            | *I*=[+0.5000,+0.0500]                |
| **中心化差值 \*δ\***           | *δ**p**a**p**er*=[−0.1605,+0.1605]        | delta=[+0.2250,−0.2250]          | delta*f**l**i**p*=[−0.2250,+0.2250]  |
| **Logits 更新公式**            | *w*←*w*−*β**δ**p**a**p**er*               | *w*←*w*+*β*delta                 | *w*←*w*+*β*delta*f**l**i**p*         |
| **Logits 变化结果**            | *w*0↑(+0.0080),*w*1↓(−0.0080)             | *w*0↑(+0.0113),*w*1↓(−0.0113)    | *w*0↓(−0.0113),*w*1↑(+0.0113)        |

| **实际加权方向**               | 梯度向对数空间 Pareto 平衡收敛            | **强任务（改善快）被进一步加权** | **弱任务（改善慢）获得更高线性权重** |

 

分析表明：当前代码中的 `delta = improvement - avg_improvement` 配合 `+ beta * delta` 施加于线性损失，**是一个方向完全相反的自造启发式**。它在逻辑上构成了“马太效应”（强者愈强），导致改善快、梯度绝对值大的分割任务持续夺取权重，最终使分类任务因表征空间被压制而退化至 AUC 0.51–0.53。  

## 二、 符号极性分析与侧效应评估 (Q2 深度解答)

### 2.1 符号反转的极性推导与救弱任务逻辑

若要达成“给改善慢（欠优化）的任务更高线性权重”的目标，必须纠正符号极性。 极性推导如下： 设 *I**k* 为任务 *k* 的线性改善率，*I**k*>*I*ˉ 表示该任务学得比平均水平快；*I**k*<*I*ˉ 表示该任务学得比平均水平慢。 为提升慢任务的线性损失权重，需使其 Logits *w**k* 增加。定义正确的 Logits 增量方向为：  

Δ*w**k*∝−(*I**k*−*I*ˉ)=*I*ˉ−*I**k*

因此，更新语句必须修改为： `w_logits = w_logits + self.beta * (avg_improvement - improvement) - self.gamma * self.w_logits` 或等价写作： `w_logits = w_logits - self.beta * delta - self.gamma * self.w_logits`  

### 2.2 符号反转后的侧效应评估

1. **与 \*L\*2 正则项（−\*γ\**w\**l\**o\**g\**i\**t\**s\*）的交互**： 正则项 −*γ**w**l**o**g**i**t**s* 始终充当“向原点（均等权重）拉回”的衰减力。当符号取反后，若某任务长期改善缓慢，`w_logits` 会增长，直到增量 *β*(*I*ˉ−*I**k*) 与正则阻力 *γ**w**k* 达到动态平衡。正则项在反号后仍然发挥抑制 Logits 无限膨胀的作用，二者物理语义完全兼容。  
2. **与 Softmax 平移不变性的交互**： 由于 ∑*k*=1*K*(*I*ˉ−*I**k*)=*K**I*ˉ−∑*k*=1*K**I**k*=0，增量向量的总和恒为 0。这保证了 Logits 的均值不会发生整体漂移，符合 Softmax 的数值稳定要求，不会引发零点偏移或概率坍缩。  
3. **极端异常场景（噪声任务 / 无法收敛任务）的风险**： 若 5 个任务中存在一个标注质量差或极难收敛的“坏任务”（如某种物理先验损失无法降低），*I**ba**d*≪*I*ˉ 将持续成立。反号后，系统会向该坏任务倾斜权重。 *防护措施*：代码中已保留的 `torch.clamp(self.w_logits, min=-10.0, max=10.0)` 和 `improvement = torch.clamp(improvement, min=-2.0, max=2.0)` 能设定权重上限，防止极端恶化。  

## 三、 数值稳定性、小损失分母与超参数校验 (Q3 深度解答)

### 3.1 小损失分母与数值波动分析

在甲状腺超声多任务模型中，分割任务（如 Dice Loss）在训练中后期损失值会衰减至极小值（如 0.01∼0.001）。 当前实现的分母为：

denominator=∣*L**t*−1∣+1*e*−4

当 *L**t*−1=1*e*−4 时，若损失因 Batch 间数据抖动从 1*e*−4 变动至 2*e*−4，微小的绝对变化（1*e*−4）会导致改善率被计算为：

*I*=1*e*−4+1*e*−41*e*−4−2*e*−4=−0.5

即产生剧烈的改善率波动。虽然 `clamp(improvement, -2.0, 2.0)` 能截断极值，但无法消除在零点附近由 Batch 噪声引起的频发高幅震荡，导致 Logits 颠簸。  

**原论文的解决之道**：

1. **基准平移**：原论文 Algorithm 1 明确要求 *L**i*≥*ϵ*>0，建议使用 *L**i*←*L**i*−*L**i*∗+*ϵ*，其中 *L**i*∗=inf*θ**L**i*(*θ*) 为损失下界。  
2. **对数空间平滑**：对数差分 log(*L**t*+*ϵ*)−log(*L**t*−1+*ϵ*)=log(1+*L**t*−1+*ϵ**L**t*−*L**t*−1)，当 *ϵ*=1*e*−8 且配合绝对损失偏移时，数值表现比直接除以小分母更加平滑。  

**工程建议修改**： 若维持简化启发式，建议将分母的平移量增大至与任务损失量级相匹配的水平，例如 `1e-2` 或采用指数移动平均（EMA）平滑后的损失计算改善率： `improvement = (self.prev_loss - losses_tensor.detach()) / (torch.abs(self.prev_loss) + 1e-2)`

### 3.2 超参数 *β*=0.05,*γ*=0.001 的合理性

下表对照了原论文推荐设置与当前甲状腺多任务工程设置：

| 超参数                | 原论文推荐值 (NeurIPS 2023)   | 当前工程实现 (`famo.py`) | 适用性与评估结论                                             |
| --------------------- | ----------------------------- | ------------------------ | ------------------------------------------------------------ |
| **Logits 步长 \*β\*** | 0.01∼0.05（默认 0.025）       | 0.05                     | **合理但偏大**。在 5 Task 且使用线性改善率时，建议调小至 0.01∼0.025，防止权重震荡。 |
| **权重衰减 \*γ\***    | 0.001                         | 0.001                    | **完全一致**。有效地将未受强信号驱动的 Logits 牵引回 0。     |
| ** Logits 截断**      | 未显式截断（靠 *γ* 隐式约束） | [−10.0,10.0]             | **合理防护**。防止 Softmax 出现数值溢出或极化（产生 One-hot 权重）。 |
| **改善率截断**        | 未设硬截断                    | [−2.0,2.0]               | **必要防护**。能消除因个别 Batch 损失突变引起的极端异常梯度。 |

 

## 四、 架构演进路线与工程落地权衡 (Q4 深度解答)

针对本项目（5 任务、少样本 500–2000 例、O(1) 边缘算力约束），提供两种可行的工程重构方案。

### 4.1 方案对比与决策矩阵

下表对“修正符号的启发式方案”与“升级为原论文标准 FAMO 方案”进行了维度比对：

| ---------------------------- | --------------------------------------- | ------------------------------------------------------- |

| **理论完备性**               | 无收敛性证明，属于工程经验规则          | 严格遵从 NeurIPS 2023 论文，具有 Pareto 收敛保证        |
| **计算与内存开销**           | O(1) 空间 / O(1) 时间                   | O(1) 空间 / O(1) 时间                                   |

### 4.2 工程权衡与实施建议

**推荐策略**：采取**两阶段推进路线**。

1. **第一阶段（紧急修复）：采用方案 A（修正符号极性）**
   - **理由**：直接阻断分类 AUC 退化至 0.51 的 Bug，改动风险最小，可立即在 A800 训练侧验证梯度流向。  
   - **核心逻辑修改**： 将 `delta = improvement - avg_improvement` 改为 `delta = avg_improvement - improvement`（慢任务得到正 `delta`，增加 Logits）。  
2. **第二阶段（架构演进）：升级为方案 B（标准 FAMO 模块）**
   - **理由**：甲状腺超声数据集样本量较小（500–2000 例），多任务间损失量级差异悬殊（分割 Dice Loss 约为 0.1~0.3，良恶性 BCE Loss 约为 0.5~0.7，SupCon Loss 约为 1.5~3.0）。标准 FAMO 依靠对数空间求导，能从数学机制上消除不同任务损失绝对量级不同带来的梯度支配问题。  

## 五、 自动化回归测试与门禁方向断言设计

### 5.1 `gate4_famo.py` 门禁漏洞根因

现有的测试脚本 `gate4_famo.py` 仅检验了 `w_logits` 是否包含 NaN 以及值在更新后是否发生改变。这种“只验存在性、不验方向性”的弱断言，是导致符号反向 Bug 长期未被发现的直接原因。

### 5.2 防御性方向断言测试规范

必须在测试套件（如 `tests/models/test_famo.py`）中补全**方向极性断言**。测试用例应当构造可控的数据，验证在“强任务改善快、弱任务改善慢”的前提下，权重的调整方向符合预期。

测试逻辑设计如下：

Python

```
import torch

def test_famo_directional_correctness():
    """
    方向性断言测试：验证 FAMO 是否给改善慢（弱任务）加权、给改善快（强任务）减权
    """
    scheduler = FAMOScheduler(num_tasks=2, beta=0.05, gamma=0.0)
    
    # 第 0 步：初始化 prev_loss
    initial_loss = torch.tensor([1.0, 1.0])
    scheduler.get_weighted_loss(initial_loss, update_weights=True)
    
    # 第 1 步：构造差异化改善
    # Task 0 (强任务): Loss 从 1.0 降至 0.5 (改善率 0.50, 改善快)

    _, weights = scheduler.get_weighted_loss(next_loss, update_weights=True)

    # 极性断言 2：弱任务分配到的 Softmax 权重必须大于 0.5
    assert weights[1] > 0.5, \
        f"方向错误！改善慢的任务权重 ({weights[1]:.4f}) 应该大于 0.5"
        
    # 极性断言 3：Logits 的变化量符号检查
    assert scheduler.w_logits[1] > 0.0, "弱任务 Logits 增量应为正"
```
